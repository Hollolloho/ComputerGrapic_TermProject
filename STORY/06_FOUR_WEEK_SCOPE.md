## 2. 4주 제출 목표: 현재 살인 사건의 짧은 완결

**여관의 작은 조사 구역에서 잔향·기록·증언을 대조해 에드윈 살인범이 카일임을 입증하고 종료하는 게임**을 목표로 제안한다. 첫 플레이 약 10분을 목표로 하되 실제 테스트로 조정한다.

7년 전 화재와 잔향 거래는 현재 범행의 동기를 이해하는 데 필요한 배경으로 전달한다. 과거 사건의 모든 책임을 플레이어가 독립적으로 수사·판결하는 분량은 추가 확장으로 둔다. 기존 이야기의 사실을 삭제하거나 바꾸는 것은 아니다.

| 항목 | 제출본의 상한·표현 |
|---|---|
| 공간 | 여관 기록실 1개와 짧은 통로. 현재와 과거가 같은 공간을 사용 |
| 인물 | 대화 대상 최대 3명: 마리·레온·카일. 고정 위치와 글 대사 사용 |
| 다른 인물 | 에드윈은 피해자와 조사 기록으로, 노아와 구매 귀족은 문서 속 인물로 전달 |
| 잔향 | 정지된 과거 1개. 관찰·이동만 가능하며 과거 변경·대화·새 기록 기능 없음 |
| 단서 | 카드 6~8개 이내를 목표. 필요한 입증이 이 범위에서 가능한지 먼저 설계 |
| 추리 | 관찰에 따른 중간 판단 1개와 범인·근거를 고르는 최종 판단 1개 |
| 결말 | 정답 결말 1개. 오답·근거 부족은 안내 후 재조사, 별도 분기 결말 없음 |
| 진행 | 시작 안내 → 현재 조사 → 잔향 관찰 → 증언·기록 대조 → 최종 제출 → 결과·재시작 |
| 그래픽스 | 프로젝트 필수 카메라 5가지, 시간에 따른 안개·FOV 전환, 단순한 3D 배치와 가림 관계 |

카메라 5가지는 확대·이동·자전·공전·부모 변환 결합이다. 이는 프로젝트에서 정한 필수 범위이며, 과제 PDF가 동일한 다섯 항목을 직접 지정했다는 뜻은 아니다. 정지된 잔향에서도 전환 효과의 시간 변화와 사용자 입력에 따른 화면·게임 상태 변화를 시연한다.

최대치는 제작 목표량이 아니다. 단서 8개나 NPC 3명을 반드시 채우지 않는다. 그래픽스 동작은 [기존 카메라 기준](../DEVELOPMENT/02_REQUIRED_CAMERA.md)과 [잔향·입력 기준](../DEVELOPMENT/03_ECHO_AND_INPUT.md)을 따른다.

첫 구매 귀족의 동기·가족의 휴양차 방문·정원에서 꽃을 내밀며 웃는 아이의 장면은 채택했다. 그 순간이 기록된 조건과 카일이 잔향을 먼저 확보한 뒤 구매자를 찾는 방식은 아직 제안 또는 미정이다. 《세상의 마지막 기차역》과 《기적을 담는 카메라》는 감정 구조의 참고이며 작품의 능력을 게임 규칙으로 채택한 것이 아니다. 기억 손실을 플레이 규칙으로 추가하지 않는다.

**최종 유죄 판단에 필요한 단서는 모두 기본 제출본 안에 있어야 한다.** 추가 잔향·추가 NPC·자백에서 처음 나오는 정보가 있어야 정답이 성립하는 구조는 허용하지 않는다. 과거 사건의 배경 설명과 플레이어가 직접 입증한 사실은 결말에서 구분한다.

## 4. 범위 확정 전에 해결할 기획

각 항목에서 사용자가 결정할 세부, 작성할 대사·단서·배치도와 완료 기준은 [세부 기획 목록](05_OPEN_DECISIONS.md)에 정리한다.

한 번에 한 항목씩 결정하되, 첫 주에 다음 연결을 완성하는 것을 목표로 한다.

1. 채택한 아이의 정원 장면이 기록된 조건과 그 잔향을 확보·확인·판매하는 경로를 정한다.
2. 이번 사건에 필요한 잔향의 기록 시점·범위·재생 조건과 금지 이유를 정한다. 외부 새 기록·덮어쓰기 기능은 기본 제출본에서 사용하지 않는다.
3. 에드윈이 확보한 자료와 전달 상태, 카일이 살인으로 막으려 한 것을 정한다.
4. 현재 살인의 방법·생존 확인·발견 사이 시간표·관련자 동선을 정한다.
5. 잔향에서 보이는 사실과 문서·현장·증언의 역할을 나누고, 현재 살인의 해답이 카일 한 명에게만 성립하는지 확인한다.

범행 수법과 단서는 아직 미정이다. 따라서 이 문서는 완성된 사건 대본이 아니다. 단서 수를 맞추려고 추론을 생략하지 말고, 1개 잔향과 작은 공간으로 입증하기 어려우면 범행 설계를 단순하게 한다.

[기존 시야 퍼즐](../DEVELOPMENT/08_PROTOTYPE_CASE.md)은 목격 진술의 신뢰성을 확인하는 기능 초안이다. 그대로 최종 살인 입증으로 사용할 수 없다. 본편에 채택하려면 실제 시간표와 맞추고 독립적인 유죄 근거를 설계해야 한다.

## 5. 추가 구현의 우선순위

기본 제출본이 처음부터 결말까지 동작하고, 외부 플레이어가 근거를 설명할 수 있을 때만 다음을 검토한다. 각 항목은 독립적으로 보류할 수 있다.

| 순위 | 추가할 내용 | 조건·중단 기준 |
|---|---|---|
| 1 | 글자·대사 가독성, 조작 안내, 막히는 구간의 선택형 힌트 보강 | 이미 진행을 막는 문제는 기본 수정에 포함. 추가 연출보다 이해도를 우선 |
| 2 | 효과음·배경음, 조명·색상 보강, 장식 모델 일부 교체 | 기본 입력·충돌·시야·단서 의미를 바꾸지 않음. 사운드는 FMOD, 외부 모델은 Assimp라는 기존 계획을 따름 |
| 3 | 같은 방의 추가 잔향 1개 또는 짧은 선택 기록 | 새 공간 없이 맥락을 보충하며, 없어도 기본 사건의 입증과 결말이 완성되어야 함 |
| 제출 이후 권장 | 노아의 직접 등장, 과거 방화·치료 지연의 독립 수사, 귀족의 별도 에피소드 | 이야기 채택과 시간표·증거 재검토 후 범위를 다시 산정 |
| 제출 이후 권장 | 레온의 살인 시도 반전, 다중 결말, 마을 전체 탐색 | 새로운 조사 구조·콘텐츠 검증이 필요하므로 4주 목표에 포함하지 않음 |

음성 연기, NPC 이동·생활 패턴, 실시간 화재·과거 재연, 전투, 저장·불러오기, 잔향의 촬영·편집 기능은 이번 범위에 포함하지 않는다. 표현 보강도 11월 29일까지 검증을 마치기 어려우면 제외한다.

### 일정이 밀릴 때의 제출 범위

기존 [기본 시제품](../DEVELOPMENT/01_SCOPE.md)으로 줄인다: 방 하나·짧은 통로·마리와 레온 2명·잔향 1개·카드 4개·목격 검증 1문항·약 3~5분. 해당 초안을 채택하고 실행 검증하는 과정은 여전히 필요하다.

이 경우 카일 살인 입증과 전체 사건 결말은 포함하지 않는다. 제안서 대비 축소 이유를 최종 보고서에 적고 **조사 시제품**으로 소개한다. 카메라 5가지·한글·현재 복귀·충돌·추리의 공정성·제출물은 축소하지 않는다.

## 7. 문서와 개발 작업의 경계

이 문서는 기획 채팅에서 관리하는 범위 제안이다. 기존 DEVELOPMENT 문서의 3~5분 시제품 계획과 제품 작업 ID·완료 체크를 변경하지 않았다. 이 제안이 채택되면 제출 목표와 시제품의 관계를 관련 문서에 반영하고, 실제 구현·진척·실행 확인은 개발 채팅에서 관리한다.
