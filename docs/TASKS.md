# AEGIS 저항 작전 작업 목록

가제 AEGIS 저항 작전의 실제 구현·검증 상태를 관리한다. 기획과 제출 제안서의 기준은 [프로젝트 기획서](프로젝트_기획서.md)다. 기준일은 2026-11-10이다.

A는 홍준호로 3D·카메라·플레이어 충돌·시간 기반을 담당하고, B는 윤형균으로 전투·적·보스·UI를 담당한다. 에셋 연결·통합·테스트·제출은 함께 확인한다. 각 항목은 선행 작업을 마친 뒤 진행하며 변경 파일과 실행 결과를 남긴다. 문서 작성, 형상 생성, 컴파일 성공만으로 게임 기능을 완료 처리하지 않는다.

## 1 현재 확인된 에셋 시제품

아래 항목은 브라우저 시제품에서 확인했다. 근거 파일은 로컬 작업 폴더의 `prototypes/drone-corridor/` 기준이다.

`codex/framework`의 Assimp 로더는 OBJ와 연결된 MTL에서 형상·메시·재질을 읽는다. 솔루션·라이브러리·로더는 아직 `main`에 병합하지 않았다. T005·T006에서는 이 데이터를 OpenGL 렌더링에 연결한다. 움직이는 드론 부품에는 `assembly.json`의 조립 원점과 회전축을 별도로 적용한다. 안내판 글자는 미리보기 전용이다. 조명·그림자·발광과 움직임은 OpenGL에서 구현하고 충돌은 게임 장면에서 검증한다.

## 5 시간 규칙과 기본 전투

초기 시간 배율은 실제 XZ 이동 속도에 따라 0.05~1배다. 마우스 회전과 확대는 배율을 바꾸지 않는다. Shift를 누르는 동안에는 이동 없이도 1배로 진행한다. 발사는 0.25초의 실제 시간 동안 1배 진행을 발생시키며 그동안 재발사를 막는다. 이 수치는 초기 조정값이고 변경 시 기획서와 이 파일을 함께 맞춘다.

적·탄환·보스·세계 효과는 `gameDt = realDt × timeScale`을 사용하고 플레이어 이동·카메라·UI는 `realDt`를 사용한다. Pause·포커스 상실·분석 화면에서는 세계 배율을 0으로 하고 플레이어 이동·사격과 발사 진행 타이머도 멈춘다. 분석 카메라와 UI 조작만 허용한다.

## 8 범위 조정 원칙

- 11/15에 기반이 막히면 새 모델 제작을 멈추고 기존 드론·복도와 단순한 색상으로 실행·충돌·카메라를 먼저 확보한다.
- 11/22까지 전체 진행이 연결되지 않으면 방과 적의 수, 추가 조명·음성·복잡한 보스 연출을 줄인다. 작은 전투 구역과 코어실을 이어 완결하고 비행 입자와 고정 패턴 파편은 단순한 형상으로 적용한다.
- 시간 전투, 카메라 다섯 기능, 중앙 AI 코어 보스, 안전한 재시작·종료는 유지한다. 최종 보스를 제거한 일반 적 사격 시제품을 완성 게임으로 표시하지 않는다.
- 기존 에셋과 단색 재질을 우선한다. 인간형 적·인간 NPC 애니메이션·범용 길찾기·다수 무기·근접전·온라인 협동·자유 저장·대규모 도시·리플레이 편집기는 기본 범위에 넣지 않는다.
- 실제로 완료한 항목만 체크하고, 실패 항목에는 재현 조건·원인·조치·재확인 결과를 남긴다. 현재 체크된 V 항목을 게임 구현 T 항목의 완료 근거로 대신하지 않는다.
