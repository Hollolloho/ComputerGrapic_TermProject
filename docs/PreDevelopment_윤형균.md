## 처음 GitHub로 협업하기

공용 브랜치는 두 사람이 합친 작업을 두는 곳이다. 전투 코드는 **개인 작업 브랜치 `feature/yoon-combat`**에서 수정한다. 커밋은 내 PC에 변경을 기록하고, 푸시는 그 커밋을 GitHub에 올린다. 풀 리퀘스트(PR)는 개인 브랜치의 변경을 공용 브랜치에 합치기 전에 검토를 요청하는 절차다.

### 1. 저장소 받기

GitHub 계정으로 [팀 저장소](https://github.com/Hollolloho/ComputerGrapic_TermProject)에 접근할 수 있는지 확인한다. 협업 초대를 받은 경우 수락한다. PowerShell에서 Git 설치를 확인한 뒤, 저장소를 둘 상위 폴더에서 아래 명령을 실행한다.

```powershell
git --version
git clone https://github.com/Hollolloho/ComputerGrapic_TermProject.git
cd ComputerGrapic_TermProject
```

이미 저장소를 받은 경우에는 그 폴더에서 PowerShell을 열고 `git remote -v`로 `origin`이 팀 저장소를 가리키는지 확인한다. 이 문서의 기준 커밋이 원격에 올라왔는지도 홍준호와 확인한다. 로컬 시제품 에셋은 두 사람이 별도로 같은 버전을 맞춘다.

### 2. 내 작업 브랜치 만들기

아래 예시에서는 `main`을 공용 기준으로 삼는다. 기존 작업 폴더를 쓰는 경우에는 `git status`로 작업 중인 변경을 먼저 확인한다.

```powershell
git fetch origin
git switch --no-track -c feature/yoon-combat origin/main
git status -sb
```

첫 줄에 `feature/yoon-combat`이 보이면 그 브랜치에서 코드를 수정한다. `--no-track`을 사용하면 개인 브랜치의 원격 연결을 첫 푸시에서 설정할 수 있다. 다음에 작업을 이어갈 때는 `git switch feature/yoon-combat`으로 돌아온다.

### 3. 수정한 파일 검토하고 커밋하기

작업 하나를 끝내면 빌드·실행으로 확인하고 아래 순서로 기록한다. `git add` 줄의 경로는 `git status`에 표시된 실제 파일 경로로 바꾼다. 첫 커밋에서 작성자 설정이 필요하다는 오류가 나오면 이 저장소에서 `git config user.name "본인 이름"`과 `git config user.email "본인 이메일"`을 설정한다.

```powershell
git status -sb
git diff
git add -- "수정한_파일_경로"
git diff --cached --stat
git commit -m "feat: 탄환 첫 충돌 판정 추가"
```

`git diff --cached --stat`에서 이번 작업 파일만 들어갔는지 확인한다. 로컬 OBJ·빌드 출력·개인 설정은 팀이 공유 범위를 정할 때까지 각 PC에서 관리한다.

### 4. 개인 브랜치를 올리고 PR 열기

```powershell
git push -u origin feature/yoon-combat
```

첫 푸시가 성공하면 이후에는 같은 브랜치에서 `git push`로 커밋을 추가한다. GitHub에서 PR을 열 때 **공용 브랜치(base)는 `main`**, **내 작업 브랜치(compare)는 `feature/yoon-combat`**으로 고른다. 작업 ID, 바뀐 동작, 직접 실행한 확인 방법을 적고 홍준호와 검토한다.

### 5. 공용 브랜치의 변경 가져오기

홍준호가 공용 브랜치에 변경을 합쳤다면, 내 브랜치에서 `git status -sb`로 브랜치 이름과 미커밋 변경을 확인한다. 작업 폴더가 깨끗할 때 `git fetch origin`으로 원격 정보를 받고 `git merge origin/main`으로 공용 변경을 내 브랜치에 합친다. 충돌이 표시되면 `git status`로 파일을 확인해 함께 정리한다. 합친 뒤 빌드·실행을 확인하고 다시 푸시한다.

## 첫 작업 전에 맞출 것

1. **기존 실습 실행 확인(T002).** 두 PC에서 같은 실습 버전과 `x64` 설정을 사용한다. Visual Studio에서 `Pratice_Grapic.slnx`를 열고 빌드 구성, MSVC 도구 집합, Windows SDK, 실행 디렉터리를 확인한다. 실행이 막히면 첫 오류와 재현 순서를 홍준호에게 전달한다.
2. **게임 창 확인.** 홍준호가 만든 게임 대상(T003)을 받아 각자 PC에서 별도로 `Debug x64`와 `Release x64`를 실행한다. 한글 문구는 UTF-8로 관리하고 한글을 표시할 수 있는 글꼴과 함께 안내 문장 한 줄, 클릭 버튼 하나부터 띄운다. 한 번 클릭했을 때 이벤트도 한 번인지 본다(T004).
3. **복도 시험 장면 준비(T006, T008 공동).** 두 PC가 같은 시제품을 쓰는지 확인한다. 복도 한 구간, 벽 하나, 엄폐물, 플레이어 시작점, 임시 표적부터 배치한다. 복도 OBJ와 연결된 MTL을 게임의 Assimp 로더로 확인하고, 메시별 색을 홍준호와 맞춘다. 이동 충돌을 붙일 수 있도록 벽·문·엄폐물의 위치와 크기를 전달한다.

### 공유한 Visual Studio 설정으로 빌드하기

공용 브랜치의 게임 솔루션 `AEGIS.slnx`, 프로젝트 `game/AEGIS.vcxproj`, `external/` 라이브러리를 같은 커밋에서 받는다. `external/`은 **`.slnx`가 있는 폴더 바로 아래**에 둔다.

1. 받은 `.slnx`를 Visual Studio에서 연다. 홍준호와 같은 MSVC 도구 집합과 Windows SDK가 설치되어 있는지 확인한다.
2. 상단 구성에서 **`Debug | x64`**를 선택하고 솔루션을 빌드한 뒤 게임 창을 실행한다. 제출용 실행을 확인할 때는 `Release | x64`로 다시 빌드한다.
3. 오류가 나면 첫 오류 메시지와 빌드 구성을 기록한다. 헤더나 `.lib`를 못 찾으면 `external/`의 위치와 라이브러리 버전을, 실행할 때 GLEW·Assimp DLL 오류가 나면 빌드 후 DLL이 실행 파일 옆에 복사됐는지 확인한다.

프로젝트의 헤더·라이브러리 경로는 **`$(SolutionDir)external\...`** 형식을 쓴다. `$(SolutionDir)`는 Visual Studio가 현재 연 솔루션의 폴더 경로로 바꿔 준다. 예를 들어 `$(SolutionDir)external\glfw\include`는 형균이 PC에서도 받은 솔루션 옆의 `external\glfw\include`를 가리킨다. 각자 저장소를 둔 위치가 달라도 프로젝트 설정은 그대로 쓸 수 있다. `.vs/`, `.vcxproj.user`, 빌드 결과물은 각 PC에서 관리한다.

## 사격과 충돌 구현 기준

- `Playing`에서 무기를 든 상태의 새 좌클릭만 발사 요청으로 받는다. 실제 발사에 성공하면 홍준호의 시간 계산에 신호를 보내 약 0.25초 동안 1배속으로 진행하고 재발사를 제한한다. 버튼을 누른 채 유지하거나 UI를 클릭하는 입력은 전투 사격으로 전달하지 않는다.
- 탄환·적·보스는 홍준호가 넘기는 `gameDt`로 움직인다. 탄환마다 **이전 위치에서 이번 위치까지** 벽·장갑·몸·무기와 교차를 검사한다. 가장 가까운 교차 한 곳을 확정하고 피해와 탄환 제거를 처리한다. 이동 위치와 첫 충돌 지점은 홍준호의 잔상·파편 효과에 전달한다.
- 플레이어 몸과 장착 무기는 다른 경계체로 검사한다. 화면의 무기 위치와 충돌 위치가 맞도록 홍준호가 제공한 카메라·장착 위치를 사용한다. **탄환은 발사한 무기 ID를 가진다.** 유효타 시 현재 장착한 ID가 일치할 때만 그 무기를 깨뜨린다.

## 무기 파손·회수와 실패 처리

| 재현 상황 | 기대 결과 |
|---|---|
| 적탄이 내 무기에 먼저 닿음 | 적탄과 무기가 깨진다. 그 탄으로 몸 피해는 생기지 않고, 빈손 상태가 HUD에 표시된다. |
| 적탄이 내 몸에 먼저 닿음 | 몸 피해를 한 번 적용한다. 체력이 0이면 전투를 멈추고, 실패 화면에서 수정 파편 효과를 실제 시간으로 한 번 재생한 뒤 재시작을 받는다. |
| 내 탄이 적 본체 또는 열린 약점에 유효타를 냄 | 피해를 적용하고 발사 무기가 아직 장착되어 있으면 파괴한다. 이미 다른 무기를 장착했다면 현재 무기를 유지한다. |
| 내 탄이 일반 적 무기에 먼저 닿음 | 적 무기만 파손되고 그 적은 사격을 멈춘다. 적 몸과 플레이어 무기는 유지된다. |
| 일반 적이 파괴됨 | 온전한 무기는 회수 물체 하나로 남는다. 파손된 무기는 떨어지지 않는다. 온전한 무기는 적 파괴용 파편과 중복해서 그리지 않는다. |
| 빈손으로 무기 또는 보급대 앞에서 E 입력 | 가까이 바라보는 대상 하나와 상호작용한다. 회수한 물체는 장착과 동시에 사라진다. 각 전투 구역에 보급대를 두고 코어실에서는 엄폐 뒤에서 다시 무장할 수 있게 한다. |

재시작은 현재 구역을 처음 상태로 되돌린다. 체력·장착 무기·드롭·적 무기 파손 상태·탄환·파티클·적·보스·문·시간 배율·사격 진행 타이머·카메라·UI를 한 번에 복원한다. E 입력은 회수·보급·분석·진행 장치 중 한 대상에만 사용한다.

## 통합 전에 재현할 장면

1. **벽이 앞에 있는 표적.** 얇은 벽 뒤에 적을 두고 정지·이동·Shift에서 사격한다. 각 경우 벽이 첫 충돌로 처리되고 적은 피해를 받지 않는다.
2. **무기와 몸이 겹쳐 보이는 각도.** 적탄 한 발이 가장 먼저 맞은 부위만 처리되는지 확인한다. 몸과 무기에 같은 탄의 결과가 중복되면 충돌 후보를 고르는 부분부터 확인한다.
3. **이전 무기에서 나간 탄.** 첫 무기의 탄이 날아가는 동안 그 무기가 적탄에 파손되게 한다. 다른 무기를 주운 뒤 첫 탄이 유효타를 내도 새 무기는 유지된다.
4. **온전한 드롭과 파손된 무기.** 적 본체를 바로 맞힌 경우에는 무기를 한 번 회수할 수 있다. 적 무기를 먼저 깨고 본체를 파괴한 경우에는 드롭이 없다. 무기를 들고 있는 상태에서 E를 눌러도 중복 장착되지 않는다.
5. **코어실에서 빈손이 되는 상황.** 약점 명중과 적탄 피격으로 무기를 잃는 경우를 각각 재현한다. 보급을 받고 약점에 3회 유효타를 내면 한 번만 클리어된다. 실패 후 재시작하면 같은 상황을 처음부터 다시 만들 수 있다.

작업을 넘길 때는 작업 ID, 커밋, 빌드 구성, 재현 순서, 관찰 결과를 기록한다. 첫 통합에서 홍준호와 발사 성공 신호, 벽 충돌 위치, 장착 무기 위치, 구역 재시작 초기값을 한 장면에서 확인한다.
