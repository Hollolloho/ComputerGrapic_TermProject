## 1 프로젝트 개요

우리 팀은 중앙 AI가 장악한 미래 시설에 인간 저항군이 침투하는 1인칭 전술 액션 게임을 제작한다. SUPERHOT의 움직임에 연동되는 시간 규칙을 참고하여, 느리게 움직이는 탄환을 관찰하고 이동·사격의 순서를 결정하는 전투를 구현한다. 제작한 감시 드론과 복도 모델을 사용하고, 마지막에는 중앙 AI 코어를 무력화하는 완결된 짧은 게임을 목표로 한다.

|---|---|---|

개발 환경은 기존 실습의 C++·OpenGL·GLFW·GLEW·GLM과 Visual Studio x64를 사용한다. 기존 계획의 2명 각자 하루 2~3시간, 주 5일, 약 4주 총 80~120시간에 학습과 제출 준비를 포함한다. 실제 진도에 따라 선택 표현과 적 수부터 줄인다.

### 배경과 플레이어의 목표

사회 기반 시설과 보안 기계를 장악한 중앙 AI에 맞서 인간 저항군이 활동한다. 플레이어는 저항군의 단독 침투 요원으로, 감시 구역을 돌파해 시설 중앙 AI 코어를 파괴하고 통제를 끊는다. 동료의 존재는 짧은 통신 문구로 전달한다. 사람형 NPC·주인공 전신·손 애니메이션은 기본 범위에 넣지 않는다.

배경은 깨끗하지만 감시가 강한 미래 시설이다. 흰색·회색 패널, 검은 기계 연결부, 반복되는 구역 번호와 AI 표식, 붉은 감시 렌즈로 분위기를 만든다. AEGIS와 S-07은 현재 시제품의 작업용 명칭이며 최종 명칭은 변경할 수 있다. 스카이넷처럼 시설과 기계를 통제하는 적이라는 방향을 참고하되 인물·명칭·모델·음성은 자체 구성한다.

### 핵심 규칙과 특징

플레이어가 멈추면 세계가 극도로 느려지고, 이동하면 정상 속도에 가까워진다. 정지한 상태에서 탄환 방향과 엄폐 위치를 확인한 뒤 움직일 경로와 사격 순서를 결정한다. 다음 수치는 첫 전투 시제품에서 검증할 **초기 조정값**이며, 구현 완료나 최종 밸런스를 뜻하지 않는다.

| 상황 | 시간 규칙 초안 |
|---|---|
| 수평 이동 없음 | 세계 속도 0.05배. 완전 정지는 아니므로 탄환이 아주 느리게 진행 |
| 수평 이동 | 충돌 처리 후 실제 이동 속도에 따라 세계 속도를 0.05~1배로 변경 |
| 마우스 자전·FOV 확대 | 시간 속도를 높이지 않음. 시점과 UI는 실제 시간으로 반응 |
| 좌클릭 사격 | 1회 발사 후 실제 시간 약 0.25초 동안 세계를 1배속으로 진행하며 재발사 차단 |
| Shift 유지 | 이동하지 않아도 세계를 1배속으로 진행. 탄환·보스 패턴을 기다리는 용도 |
| 일시정지·포커스 상실·분석 화면 | 세계 시간 0, 이동과 사격 차단. 복귀 시 큰 경과 시간과 눌린 입력을 정리 |

벽에 막혀 실제로 이동하지 못하면 이동키를 누르기만 해도 세계가 빨라지는 현상을 만들지 않는다. 시간 속도는 `사격 진행 중 또는 Shift 유지이면 1`, 그렇지 않으면 `0.05 + 0.95 × 실제 이동 속도 비율`로 계산한다. 속도 비율은 0~1로 제한한다.

적 이동·적과 플레이어의 탄환·적의 발사 대기·보스 패턴·전투 파괴 효과는 같은 게임 시간을 사용한다. 플레이어의 수평 이동, 시선, UI는 실제 시간을 사용한다. 사격 진행 시간과 재발사 제한은 실제 시간으로 계산하되 Pause·포커스 상실·분석 화면에서는 감소시키지 않는다. 이를 통해 정지 상태에서 적의 시간이 진행되지 않는 무료 연사를 막는다. 순간 경과 시간을 제한하고 탄환은 이전 위치부터 현재 위치까지의 선분으로 충돌을 검사한다.

### 제작 규모

| 항목 | 기본 목표 |
|---|---|
| 공간과 인물 | 안전한 진입실 → 보안 전투 구역 → 중앙 코어실, 작은 구역 3개. 인간은 1인칭 주인공과 통신 문구로 표현 |
| 전투 콘텐츠 | S-07 드론 1종, 고정 포탑 1종, 중앙 AI 보스 1종, 파괴와 회수가 가능한 단발 수정탄 무기 1종 |
| 플레이와 표현 | 첫 플레이 5~10분 목표. 반복 모듈·부품 회전·기본 조명·필요한 평면 텍스처·한글 HUD |
| 범위 제한 | 넓은 도시·멀티플레이·사람형 리깅·범용 길찾기·다종 무기·인벤토리·근접전·던지기·복잡한 장전·실시간 메시 파쇄·저장과 불러오기 제외 |

무기는 한 번에 한 자루를 든다. 발사 간격과 명중 시 파손을 관리한다. 첫 시험은 드론 1대·적탄 1개로 시작하며, 일반 적은 본체 유효타 1회로 파괴되도록 잡는다. 플레이어 체력과 탄환 속도는 시제품에서 조정한다. 실패하면 현재 구역을 재시작한다.

### 현재 제작 상태

- **준비됨:** 드론과 복도 시제품, 드론 5개 조립 그룹과 부품·재질별 OBJ 20개, 합본 드론 OBJ와 복도 OBJ, 조립 정보와 색상 데이터.
- **미리보기에서 확인됨:** 복도 이동, FOV 확대, 드론 공전, 부품 펼치기, 부유·센서·팬 동작, 정지·재생, 작은 화면 배치. 이는 브라우저 디자인 시제품의 검사 결과다.
- **게임에서 아직 미구현:** OpenGL 장면 연결, 카메라 5기능의 게임 통합, 실제 벽·탄환 충돌, 시간 전투, 적 AI, 보스전, HUD, 시작·결과·재시작·종료의 전체 흐름.

브라우저 미리보기와 에셋 사용 안내는 로컬 작업 폴더의 `prototypes/drone-corridor/`에 있다.

## 게임 진행과 예상 화면

**시작 화면 → 저항군 임무 안내 → 안전 구역의 드론 분석 → 보안 구역 전투 → 중앙 AI 보스전 → 통제 해제 결과 → 재시작 또는 종료**

진입실에서 이동·시선·시간 진행·사격을 익히고 분석 단말에서 드론의 센서와 발사기를 살펴본다. 보안 구역에서는 엄폐물을 이용해 드론과 포탑의 탄환을 피한다. 구역의 적과 적탄을 정리하면 다음 문이 열린다. 중앙 코어를 파괴하면 임무 완료를 표시한다. 사망하면 해당 구역을 재시작할 수 있다.

### 예상 화면 구성

제안서 PDF의 그림 1은 현재 제작한 3D 형상으로 렌더한 브라우저 시제품이다. 흰 장갑판과 붉은 센서를 갖춘 드론은 본체·센서·좌우 팬·하부 발사기로 구성한다. OpenGL 게임 화면에는 상단에 현재 목표, 중앙에 조준점, 하단에 체력·세계 시간 속도·조작 안내를 표시할 계획이다.

### 대표 전투 과제

복도의 드론이 사격을 예고하고 탄환을 발사한다. 플레이어는 멈춰 탄환의 진행 방향을 살피고, 짧게 옆으로 이동해 탄도를 벗어난다. 엄폐물 뒤에서 시선을 바꾸어 목표를 조준한 뒤 발사한다. 발사 순간에는 세계가 일정 시간 정상 속도로 진행하므로 적탄의 위치까지 판단해야 한다. 드론에 단순히 접근하는 조작보다 관찰·회피·사격의 순서를 선택하는 경험을 목표로 한다.

드론은 미리 정한 순찰 경로와 `순찰 → 조준 예고 → 발사 → 대기 → 파괴` 상태를 사용한다. 포탑은 고정된 자리에서 플레이어가 보이는지 확인하고 머리와 총신만 회전한다. 벽 뒤의 플레이어를 관통해 사격하지 않도록 가림을 검사한다.

중앙 AI 보스는 고정된 코어와 회전 포탑, 열리는 장갑판으로 구성한다. `공격 예고 → 탄환 발사 → 장갑 개방 → 약점 공격 기회 → 장갑 폐쇄`의 한 패턴을 먼저 완성한다. 초기 목표는 약점 유효타 3회이며 유효타가 들어오면 해당 개방을 끝낸다. 일반 적의 총신과 표시등을 재사용하고, 사람형 거대 보스나 추가 소환 패턴은 만들지 않는다.

### 수정탄과 무기 파괴·회수

수정탄은 게임 시간에 따라 날아가며, 뒤에 가느다란 청백색 잔상과 작은 빛 입자를 남긴다. 입자는 이동 거리 기준으로 생성한다. 벽·장갑·무기·본체 중 처음 맞은 지점에서 탄환을 제거하고 미리 정한 수정 조각 패턴을 한 번 재생한다. 잔상과 세계 속 파편의 움직임·수명은 `gameDt`를 사용한다.

| 상황 | 구현 기준 초안 |
|---|---|
| 적탄이 플레이어 무기에 먼저 맞음 | 무기와 적탄이 깨진다. 해당 적탄의 피해는 무기에서 끝나며 플레이어는 빈손이 된다. |
| 적탄이 플레이어 몸에 먼저 맞음 | 체력이 감소한다. 체력이 0이면 화면 앞에서 수정 조각이 퍼지는 1인칭 연출을 보여준 뒤 구역 재시작을 선택하게 한다. 이 연출은 실패 화면에서 실제 시간으로 재생한다. |
| 플레이어 탄환이 적 본체 또는 열린 코어 약점에 유효타를 냄 | 발사한 무기가 아직 손에 있으면 파괴한다. 탄환에 발사 무기 ID를 기록해 먼저 발사한 탄이 새로 주운 무기를 깨뜨리는 일을 방지한다. |
| 플레이어 탄환이 일반 적 무기에 먼저 맞음 | 해당 무기가 깨지고 적은 사격을 멈춘다. 적 본체 체력과 플레이어 무기는 유지된다. |
| 일반 적이 파괴됨 | 팬·센서 등 분리 부품이 흩어진다. 온전한 무기 모듈은 회수할 수 있는 물체 하나로 떨어진다. |

빈손으로 가까이 있는 무기를 바라보고 E를 누르면 같은 단발 무기로 장착한다. HUD에 무기 상태와 회수 안내를 표시한다. 각 전투 구역의 접근 가능한 보급대는 빈손일 때만 같은 무기를 한 자루 지급한다. 코어실에서는 엄폐 뒤에 보급대를 두어 사격 기회마다 다시 무장할 수 있게 한다.

## 2 주요 기능과 그래픽스 기술

**확대·이동·자전·공전·부모 관계**를 모두 필수로 유지한다. 다섯 개의 고정 시점이라는 뜻이 아니라 서로 구분되는 카메라 변환 기능이다. 사용자 지정 필수 조건이며 과제 안내가 이 다섯 항목을 그대로 지정했다고 단정하지 않는다. 부모 관계는 클래스 상속이 아닌 좌표 변환 행렬의 결합이다.

| 기능 | 구체적인 동작과 완료 기준 | 관련 기술 |
|---|---|---|
| 이동 CAM_MOVE | WASD로 수평 이동. 대각선 속도를 정규화하고 벽·엄폐물을 통과하지 않음 | 이동 변환·경과 시간·XZ 충돌 |
| 자전 CAM_SELF | 카메라 위치는 고정하고 yaw·pitch로 제자리 시선 회전. pitch 범위 제한 | 회전 행렬·마우스 입력 |
| 확대 CAM_ZOOM | 분석 화면에서 FOV만 35~70도로 변경. 위치와 공전 반경 고정, 닫으면 복원 | 원근 투영·FOV |
| 공전 CAM_ORBIT | 고정된 드론 복사본 주위를 카메라가 일정 반경으로 회전해 옆·뒤·밑면을 확인 | 피벗·회전 행렬·View 역행렬 |
| 부모 관계 CAM_PARENT | PlayerRoot의 이동·yaw를 EyeCamera가 따르며 로컬 눈높이와 pitch를 유지 | 계층 변환·부모 행렬 × 로컬 행렬 |

### 카메라 구조와 안전한 분석 화면

```text
PlayerRoot: 수평 위치 + yaw
  EyeCamera: 로컬 눈높이 + pitch
InspectionPivot: 분석 대상 중심 + 공전 yaw/pitch
  InspectCamera: 일정 반경의 로컬 거리
```

열벡터, 기본 시선 -Z, 부모 스케일 없음 기준으로 다음처럼 계산한다.

```text
EyeWorld = Translate(playerPosition) * RotateY(yaw)
         * Translate(0, eyeHeight, 0) * RotateX(pitch)
View = inverse(EyeWorld)
InspectWorld = Translate(pivot) * RotateY(orbitYaw)
             * RotateX(orbitPitch) * Translate(0, 0, radius)
InspectView = inverse(InspectWorld)
```

분석은 진입실의 안전 단말 또는 적과 적탄이 모두 사라진 구역에서만 연다. 세계의 실제 드론이 아닌 별도 배경의 표시용 복사본을 사용한다. **공전 검사 중 복사본은 부유·회전 애니메이션까지 정지**시켜 카메라 이동과 물체 회전을 구분한다. 공전 pitch 초기 범위는 -60~60도다. 분석 화면을 닫으면 위치·yaw·pitch·FOV·커서 모드를 복원한다. UI 클릭을 사격으로 전달하지 않으며 분석 중 세계와 사격은 정지한다.

### 에셋 제작과 OpenGL 연결

드론과 시설은 큐브·원통·모서리를 깎은 장갑판의 조합이다. 사람형 리깅·스키닝 대신 분리된 단단한 부품을 회전·이동시킨다. 벽·바닥·천장·문틀·조명 모듈을 반복하고, 드론·포탑·보스가 렌즈·총신·표시등 재질을 공유한다. 파괴 효과는 미리 만든 부품이 짧게 흩어지는 수준으로 제한한다.

- 형상 원본과 재생성 코드: `prototypes/drone-corridor/build_assets.py`
- 드론 부품·색·피벗 기준: `prototypes/drone-corridor/obj/assembly.json`
- 정적 합본: `obj/drone_assembled.obj`, `obj/corridor.obj`
- 좌표: 미터 단위, +Y 위쪽, 드론 정면 +Z. 카메라 기본 시선 -Z와 혼동하지 않도록 장면 배치 시 방향을 명시한다.
- `codex/framework`에서 관리하는 Assimp 로더는 OBJ의 메시와 연결된 MTL의 색·텍스처 참조를 읽는다. 실행 기반은 아직 `main`에 병합하지 않았다. 복도는 합본 OBJ의 메시별 재질을 사용한다. 드론 가동 부품에는 부품별 OBJ와 `assembly.json`의 조립 원점·회전축을 연결한다.
- 안내판 글자는 브라우저 미리보기 전용이다. 게임용 평면 텍스처로 별도 준비한다. 조명·그림자·발광과 애니메이션은 OBJ에 자동 포함되지 않으므로 게임에서 연결한다.
- 몸체는 단색 재질을 사용하고 번호·경고문·로고에만 평면 UV를 사용한다. 그림자·발광 번짐·고급 반사는 기본 전투 완결 후 선택적으로 검토한다.

### 구현 구조와 검증

기존 실습을 보존하고 게임 main 하나를 별도 빌드 대상으로 둔다. 처음에는 창·OBJ·카메라·충돌·탄환 하나를 연결하고, 기능이 생기는 순서대로 Camera, Scene, Combat, UI 책임을 나눈다. 범용 엔진·ECS·물리 엔진·애니메이션 임포터부터 도입하지 않는다. 상태는 Start / Playing / Inspection / Pause / Failed / Cleared로 시작하고 구역 번호와 보스 상태를 별도 데이터로 관리한다.

필수 검증은 다음과 같다.

1. 정지·이동·사격·Shift에서 적 이동·탄환·적 발사 주기·보스 패턴이 같은 게임 시간에 반응한다.
2. 마우스 회전과 휠만 조작해도 세계가 빨라지지 않고, 정지 연타와 Pause 중 입력으로 무료 사격하지 못한다.
3. 카메라 다섯 기능을 각각 수치와 화면으로 구분한다. 분석 화면 10회 왕복 후 위치·방향·FOV·입력 모드를 복원한다.
4. 프레임률 변화·포커스 복귀에도 벽과 탄환을 통과하지 않는다. 최소화 시 0 높이 투영 계산을 생략한다.
5. 같은 적탄으로 무기 파괴와 본체 피해가 함께 발생하지 않는다. 예전 무기의 탄환은 새로 주운 무기를 깨뜨리지 않으며, 온전한 적 무기만 한 번 회수할 수 있다.
6. 코어실에서 장착 무기를 잃은 뒤 보급을 받아 약점 유효타 3회를 완료한다. 구역 재시작 시 장착·떨어진 무기, 파티클, 적·탄환·체력·보스·시간·카메라·UI를 초기화한다.
7. 시작부터 중앙 AI 격파·결과·재시작·종료까지 두 PC의 Release 실행본에서 완주한다.

## 4 AI 활용 계획

ChatGPT와 Codex를 개념 학습, 기본 도형 기반 기계 에셋 생성, 코드 초안과 오류 후보 탐색, 기획·제안서 작성에 활용한다. 현재 드론·복도 형상과 브라우저 미리보기는 AI 도구로 생성하고 동작 검사한 시제품이다. 팀원은 게임에서의 크기·색·회전축·충돌·시간 규칙을 직접 확인하고 채택 여부를 판단한다.

|---|---|---|---|
| 카메라와 시간 | 행렬·FOV·시간 분리 코드 초안, 오류 후보 제안 | 회전 중심·입력 기준·시간 배율·사격 진행 규칙 결정 | 카메라 5기능, 정지 사격, Pause·복귀 검사 |
