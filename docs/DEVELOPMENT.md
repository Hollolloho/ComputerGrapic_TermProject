## 1 범위와 담당

| 항목 | 기본 목표 |
|---|---|
| 완결 | 현재 살인 사건 1건의 범인·근거 판단과 해설 |
| 공간 | 여관 방 1개와 짧은 복도, 현재/과거가 같은 좌표 사용 |
| 콘텐츠 | 대화 최대 3명, 피해자 1명, 잔향 1개, 증거 6~8개 이내 |
| 판단 | 중간 모순 검증 1회, 최종 판단 1회, 결과·재시작·종료 |
| 표현 | 기본 도형, 깊이 가림, 기본 조명·텍스처, 한글 UI, 안개·FOV 전환 |
| 플레이 시간 | 첫 플레이 5~10분 목표, 실제 테스트로 확인 |
| 홍준호 A | 3D·카메라·충돌·조사 대상 판정·잔향 전환 |
| 윤형균 B | 대화·한글 UI·수첩·클릭 선택·추리 판정·결과 화면 |
| 공동 | 사건·에셋 명세·통합·테스트·보고서·발표·영상·제출 |

2명 각자 하루 2~3시간, 주 5일 계획으로 약 4주 80~120시간에 학습과 제출 준비를 포함한다. 한글·입력 기반이 막히면 함께 해결한다. 실제 구현 여부는 두 PC에서 확인하며 문서 작성만으로 완료 처리하지 않는다.

대화 2명·카드 4개·시야 모순 1문항은 중간 시제품이다. 그 뒤 같은 공간과 시스템에 기본 사건의 나머지 증거·최종 판단을 연결한다. 전투·넓은 마을·생활형 NPC·음성·다중 결말·과거 편집·저장/불러오기는 기본 범위에서 제외한다.

## 2 필수 카메라 5가지

사용자가 정한 프로젝트 필수 조건이며 과제 안내가 이 다섯 항목을 그대로 지정했다는 뜻은 아니다.

| ID | 기능과 사용 | 완료 확인 |
|---|---|---|
| CAM_ZOOM | 상세보기 휠 FOV 확대 | 위치·반경 고정, 투영만 변경, 닫으면 복원 |
| CAM_MOVE | WASD 수평 이동 | 위치가 바뀌고 벽·가구를 통과하지 않음 |
| CAM_SELF | 마우스 제자리 자전 | 위치 고정, yaw·pitch만 변경 |
| CAM_ORBIT | 증거 중심 주위 카메라 공전 | 증거 고정, 일정 반경에서 옆·뒷면 확인 |
| CAM_PARENT | 플레이어/눈 카메라의 부모 변환 | 부모 이동 반영, 로컬 눈높이 유지 |

```text
PlayerRoot: 수평 위치 + yaw
  EyeCamera: 로컬 눈높이 + pitch
InspectionPivot: 단서 중심 + 공전 각도
  InspectCamera: 중심에서 떨어진 로컬 거리
```

열벡터 관례, 기본 시선 -Z, 부모 스케일 없음:

```text
EyeWorld = Translate(playerPosition) * RotateY(yaw)
         * Translate(0, eyeHeight, 0) * RotateX(pitch)
View = inverse(EyeWorld)
InspectWorld = Translate(pivot) * RotateY(orbitYaw)
             * RotateX(orbitPitch) * Translate(0, 0, radius)
InspectView = inverse(InspectWorld)
```

부모 관계는 상속이 아니라 행렬 결합이다. 눈 카메라의 로컬 X/Z는 0으로 두고 이동 방향은 pitch가 아닌 몸의 수평 yaw를 따른다. 대각선 이동을 정규화하고 경과 시간 기준으로 이동한다.

상세보기에서는 매개체의 표시용 복사본만 별도 배경에 그린다. 드래그로 제한된 수평·수직 공전, 휠로 FOV를 변경하며 반경은 고정한다. 초기 시험 범위는 FOV 35~70도, 공전 pitch -60~60도다. 닫으면 위치·시선·FOV·커서 모드를 복원한다. 세계 전체의 공전이나 물체 회전으로 대신하지 않는다.

## 3 입력과 상태

| 입력 | 동작 |
|---|---|
| WASD·마우스 | 탐색 이동·시선. UI 또는 전환 중 정지 |
| E | 가까운 물건 조사·대화·관찰 기록 |
| F | 매개체 근처에서 잔향 진입, 과거에서 현재 복귀 |
| Tab·클릭 | 수첩 열기·닫기, 카드·주장·범인 선택/해제·제출 |
| 드래그·휠 | 상세보기에서만 공전·확대 |
| Esc | 최상위 UI 닫기 또는 Pause. 전환 중에는 종료 후 Pause 예약 |

숫자키·Enter는 선택적 보조 입력이다. 종료는 메뉴의 명시적인 선택과 창 닫기로 제공한다.

월드 상태는 Present / Entering / Echo / Exiting, 화면 모드는 Start / Explore / Dialogue / Notebook / Inspection / Report / Result / Pause로 나눈다. 수첩을 열어도 월드는 바뀌지 않는다. 진입은 Present+Explore, 이탈은 Echo+Explore에서만 허용한다. 상세보기는 Present에서만 열고 대화·수첩·상세보기·전환 중 F를 무시한다.

중간 판단 완료와 최종 해결은 별도 플래그다. 클릭은 UI 영역에서만 처리하고 탐색 회전으로 전달하지 않는다. 전환 중 중복 입력을 차단하며 포커스 복귀 시 마우스 기준과 경과 시간을 재설정한다.

## 4 잔향 전환과 렌더링

초기 시험값은 진입 1.0~1.2초다. 0.2초까지 가장자리 안개를 짙게 하고, 0.2~0.6초에 FOV 65도에서 약 57도로 좁힌다. 약 0.65초를 넘으면 과거 배치·충돌·시작 위치를 한 번만 적용하고 FOV를 복원한다. 이탈은 약 0.6초 역전환으로 시작해 체감에 맞춰 조정한다.

안개는 가장자리에서 중심 방향으로 흐르는 알파 무늬이며 과거 탐색 중에는 바깥쪽 약 15~20%에 옅게 남긴다. 중앙과 한글 UI는 선명하게 유지한다. 흡입감은 안개와 FOV로 만들며 실제 카메라 전진은 넣지 않는다. 효과 줄이기는 전환 FOV만 생략하고 상세보기 확대는 유지한다.

진입 전 playerPosition·yaw·pitch·FOV·월드 모드를 저장한다. 과거의 안전한 시작 지점을 사용하고 현재 복귀 시 저장값을 복원한다. 과거에서 걸어간 좌표를 현재로 옮기지 않는다. 타이머가 교체 시점을 넘는지를 검사해 낮은 프레임에서도 누락·중복 없이 전환한다. Pause와 포커스 상실은 타이머·이동을 멈춘다.

렌더 순서는 3D 불투명 물체, 테두리 안개, UI다. 안개는 깊이 쓰기를 끄고 블렌딩을 적용한 후 상태를 복구한다. 과거의 벽·책장을 투명하게 만들지 않는다. 창 높이가 0이면 투영·렌더링을 건너뛴다.

## 5 최소 구조와 패턴

기존 실습의 GLFW·GLEW·GLM과 x64 구성을 먼저 확인한다. 게임 main 하나만 빌드하고 기존 실습을 보존한다. 처음에는 main에서 창·큐브·루프를 확인하고 기능이 생기면 Camera, Scene, GameData, 필요한 UI만 분리한다.

| 책임 | 데이터와 구현 방향 |
|---|---|
| 카메라 | playerPosition·yaw·pitch·eyeHeight·FOV, 독립된 상세보기 데이터 |
| 장면 | 공유 큐브 mesh, 물체 ID·변환·색·충돌·조사 ID, 현재/과거 목록 |
| 진행 | 증거 획득, 중간/최종 판단, 대사 반응, 월드·UI 상태 |
| 화면 | 고정 패널과 클릭 hit 판정. 한글 한 문장부터 시험 |

상태 기계는 enum과 전환 함수로 시작하고 진입·교체를 한 번만 실행한다. 물체는 Transform·표시·충돌·조사 데이터를 조합한다. 이를 위해 ECS·범용 장면 그래프·패턴 클래스부터 만들지 않는다. 증거 획득은 한 함수에서 수첩을 갱신하고 Pause 예약은 pendingPause 하나로 처리한다. Observer·범용 큐는 실제 복잡성이 생길 때만 검토하며 구현하지 않은 패턴을 구현했다고 설명하지 않는다.

평평한 바닥에서 XZ 부피 충돌을 사용하고 점프·중력·계단은 제외한다. 중앙 광선으로 가장 가까운 가림과 조사 거리부터 확인한다. 상세보기 복사본에 세계 조사 이벤트를 연결하지 않는다.

한글 도구는 첫 주 실행 실험으로 하나만 선택한다. 필요하면 고정 대사·카드 패널 텍스처를 사용하며 자체 글꼴 엔진은 만들지 않는다. 파일은 실행 파일 옆 assets 기준으로 찾고 누락 경로를 표시한다. 기술 개념·오류 후보에는 ChatGPT/Codex를 활용하되 팀원이 행렬·상태·정답을 결정하고 작은 실행으로 검증한다.

## 6 첫 주 에셋

| 종류 | 최소 제작·확보 내용 | 확인 |
|---|---|---|
| 공간 | 기본 도형의 방·복도·출입구·바닥·벽 | 공통 축·크기, 이동 범위 |
| 가구 | 책상·책장·의자 | 책장의 봉투 가림, 충돌 범위 |
| 증거 | 봉투·기록물·낡은 잉크통과 밑면의 여관 표식 | 조사의 구분과 글자 가독성 |
| 인물 | 고정 NPC·피해자 임시 도형 | 대화 위치와 통로 유지 |
| 표면·UI | 벽·바닥·목재 텍스처·폰트 | 형식·해상도·출처·사용 조건 |

첫 주 목표는 임시 에셋을 배치해 퍼즐을 확인하는 것이다. 정교한 모델·애니메이션은 만들지 않는다. 카메라 완성 전에도 고정 시점으로 배치와 가림을 확인한다. A는 형상·배치 연결, B는 표식·텍스트·출처를 정리하고 함께 검증한다.

출처는 파일명 / 용도 / 제작자·URL / 허용 조건 / 수정 / 표기 의무 / 배포 여부로 기록한다. 에셋 교체 시 ID·피벗·크기·충돌·단서 의미를 유지하고 가림을 재확인한다. 비상업 과제라도 실제 사용 조건을 확인한다.

## 8 완료와 제출 기준

TASKS의 Q 단계에서 다음을 실제 실행으로 확인한다.

- 시작·현재·잔향·중간/최종 판단·결과·재시작·종료가 연결되고 모든 진행 상태가 초기화된다.
- 중간 목격 모순과 살인 유죄를 구분하며, 범인만 맞히고 근거가 부족하면 완료되지 않는다. 결말의 새 정보 없이 다른 용의자를 배제할 수 있다.
- 증거 수집·선택 순서를 바꿔도 재조사·정답 접근이 가능하고 타인이 근거를 설명한다.
- 카메라 5기능과 표시·충돌·조사 데이터가 일치한다. 상세보기·잔향을 각각 10회 왕복해 위치·방향·FOV·입력을 확인한다.
- F 연타·전환 중 Tab/Esc·UI 클릭·포커스 복귀·최소화·창 크기 변경이 상태 오류나 가림 우회를 만들지 않는다.
- 조명·텍스처·안개가 단서와 한글을 가리지 않고 Release가 IDE 밖과 다른 PC에서 동작한다.

판정의 정답·오답·근거 부족은 작은 실행 검사로 남긴다. 화면과 조작은 직접 플레이로 확인하며 성공적인 컴파일만으로 검증됐다고 하지 않는다.
