# 홍준호 개발 전 준비 문서

**AEGIS 저항 작전 · 2026년 11월 10일 · 기획 기준 커밋 `e8e59bd`**

홍준호는 OpenGL 실행 기반, 카메라 5기능, 이동과 시설 충돌, 드론 에셋, 시간 계산과 수정탄 효과를 담당한다. 첫 목표는 **두 PC에서 같은 게임 창을 띄우고, 카메라로 복도 안을 이동하며 정지와 이동에 따라 탄환 속도가 달라지는 장면**을 만드는 것이다. 실제 완료 여부는 [TASKS](TASKS.md)에 기록한다.

[프로젝트 기획서](프로젝트_기획서.md) · [윤형균 개발 전 준비 문서](PreDevelopment_윤형균.md)

## 첫 작업 전에 맞출 것

1. **기존 실습 실행 확인(T001).** 로컬 `Pratice_Grapic.slnx`를 열어 `x64` 빌드 설정을 확인하고, 현재 선택된 실습을 실행한다. 실습 프로젝트에는 Windows SDK 10.0과 MSVC 도구 집합 `v145`가 지정되어 있다. OpenGL 3.3 코어 프로필을 요청하는 예제와 GLFW·GLEW·GLM 설정을 참고한다. 도구 집합과 SDK가 윤형균 PC에도 있는지 T002 결과와 비교한다.
2. **빌드 기준 공유(T003).** 사용할 구성과 플랫폼, 실행 디렉터리, 셰이더·OBJ 위치, 필요한 DLL을 한 번에 공유한다. 게임용 진입점은 별도 빌드 대상으로 둔다. 먼저 `Debug x64`와 `Release x64`에서 빈 게임 창을 열고 닫을 수 있는지 확인한다.
3. **시제품 준비.** 로컬 `prototypes/drone-corridor/`에 `obj/assembly.json`, `obj/drone_assembled.obj`, `obj/corridor.obj`, 부품·재질별 OBJ가 있는지 확인한다. 시제품 파일은 현재 커밋에 없으므로 두 PC에서 사용할 파일 목록과 버전을 따로 맞춘다.
4. **실행 기록.** 성공 화면 또는 첫 오류 메시지, 선택한 빌드 구성, 재현 순서를 기록한다. 한쪽 PC에서만 실패하면 두 설정과 실행 경로를 먼저 비교한다.

## 구현 순서와 넘길 결과

| 순서 | 작업 | 구현하고 확인할 결과 |
|---|---|---|
| 1 | T001, T003 | 윤형균의 T002 결과를 받아 공통 설정을 정한다. 두 구성에서 게임 창이 열리면 한글 화면과 테스트 복도 작업을 시작할 수 있게 실행 방법을 전달한다. |
| 2 | T005, T007 | 드론 합본으로 크기와 방향을 먼저 확인한다. 이후 재질별 OBJ를 조립해 본체·센서·좌우 팬·발사기를 분리하고 각 피벗만 움직이는지 확인한다. |
| 3 | T009~T012 | 카메라 부모 관계, 수평 이동, 자전 순서로 연결한다. 윤형균의 복도 배치(T006)를 받아 벽·문·엄폐물 충돌을 적용하고 이동 후 실제 XZ 변위를 넘긴다. |
| 4 | T018~T020, T021 공동 | 빈 장면에서 시간 갱신을 먼저 검증한다. 이동 충돌이 연결되면 실제 변위로 배율을 구한다. 윤형균의 발사 성공 신호에만 1배속 진행을 시작한다. |
| 5 | T014~T017 | 윤형균의 분석 진입 조건(T013)과 고정 드론 복사본을 연결한다. 공전·FOV 확대를 검사한 뒤 복귀 시 카메라와 입력을 복원한다. T016은 함께 확인한다. |
| 6 | T027, T028 공동, T029, T035 | 개발용 표시에서 배율·실제 변위·발사 진행 잔여 시간·적탄 수를 확인한다. 작은 전투를 함께 검증하고 코어실에 약점·장갑·엄폐물을 배치한다. 기본 조명은 전체 진행이 연결된 뒤 붙인다. |
| 7 | T043, T046 공동 | 탄환의 청백색 잔상·비행 입자·충돌 파편을 연결한다. 적 부품 비산과 플레이어 실패 연출을 통합하고 재시작 후 효과를 초기화한다. |

T018은 T003을 마치면 T012와 병행할 수 있다. T043은 T022의 탄환 이동과 충돌 위치가 확인되면 단순한 장면에서 먼저 시험한다.

## 좌표와 카메라

- 거리는 미터로 통일한다. +Y는 위쪽, 바닥은 XZ 평면이다. 드론 정면은 +Z, 카메라 기본 시선은 -Z다. 복도와 적 배치에 쓸 좌표 예시를 윤형균과 하나 맞춘다.
- 플레이어 루트에는 위치와 Y축 좌우 회전(yaw)을 둔다. 눈 카메라에는 로컬 눈높이와 로컬 X축 상하 회전(pitch)을 둔다. 카메라 월드 변환은 부모 변환과 로컬 변환의 곱이고, 뷰 행렬은 그 역행렬이다. 이동 방향은 수평 회전으로 계산하고 대각선 속도를 정규화한다.
- 분석 화면의 공전은 정지한 드론 복사본을 중심으로 일정 반경에서 카메라 위치를 움직인다. 휠은 FOV만 35~70도 안에서 바꾼다. 공전의 상하 각도는 초기 기준 ±60도다. 분석을 닫으면 위치·회전·FOV·커서 모드를 복원하고 남은 입력을 지운다.
- 드론 부품 배치는 `assembly.json`의 그룹 원점과 색을 따른다. 조립은 **드론 월드 변환 × 그룹 원점 이동 × 부품 회전** 순서로 적용한다. 센서·팬은 Y축, 발사기는 X축을 쓴다. 게임의 Assimp 로더가 넘긴 메시별 MTL 색을 렌더링에 연결하고, 복도 재질은 T006에서 함께 확인한다.

## 전투 코드와 맞출 기준

| 넘길 정보 | 맞출 동작 |
|---|---|
| 실제 시간과 게임 시간 | 실제 시간 `realDt`로 플레이어를 이동시킨 뒤 충돌 해결 후 XZ 변위로 배율을 구한다. 정지·벽에 막힘은 0.05배, 정상 이동은 최대 1배다. 적·탄환·세계 파편은 `gameDt = realDt × timeScale`을 쓴다. |
| 발사와 모드 전환 | 윤형균 쪽에서 실제 발사를 승인한 프레임부터 약 0.25초 동안 1배속으로 진행한다. Shift 유지 중에도 1배다. Pause·포커스 상실·분석 중에는 게임 시간과 사격 진행 타이머를 멈추고 플레이어 이동·사격을 막는다. 분석 카메라와 UI 입력은 해당 상태에서 처리한다. |
| 플레이어 몸과 무기 위치 | 카메라의 월드 위치·정면과 렌더링에 쓰는 장착 위치를 공유한다. 윤형균은 이 위치에 맞춰 몸과 무기 경계체를 각각 검사한다. 탄환이 화면에 보이는 무기와 다른 위치에서 막히는 경우를 함께 확인한다. |
| 탄환 이동과 충돌 이벤트 | 윤형균 쪽에서 이전 위치·현재 위치와 첫 충돌 지점을 넘긴다. 잔상은 움직인 거리만큼 생성하고 정지한 프레임의 입자 생성은 건너뛴다. 첫 충돌 지점에서 고정된 파편 패턴을 한 번 재생한다. |

## 내 PC에서 먼저 확인할 장면

| 검사 | 통과 기준 |
|---|---|
| 부모 관계·이동·자전 | 부모가 이동하고 Y축으로 돌면 눈 카메라가 따라간다. 제자리에서 마우스를 돌리면 위치는 고정되고, 위를 봐도 WASD 이동은 바닥을 따른다. |
| 공전·확대·복귀 | 드론은 정지한 채 카메라가 움직인다. 휠을 돌려도 공전 반경은 유지된다. 분석을 열고 닫는 동작을 10회 반복해 카메라와 커서가 복원되는지 확인한다. |
| 시간 배율 | 정지·벽에 막힌 상태·시선 회전만 할 때 0.05배, 정상 이동·Shift·발사 직후에는 1배다. 분석·일시정지에서 탄환과 파편이 정지한다. |
| 비행 입자와 파편 | 저속과 정상 속도에서 같은 거리를 이동할 때 궤적의 밀도가 비슷하다. 벽에 맞은 탄환은 충돌점을 지나지 않고 파편을 한 번만 남긴다. |
| 프레임률과 복귀 | 30·60·144 FPS에서 이동과 시간 규칙을 비교한다. 창을 최소화하거나 포커스를 잃었다가 돌아와도 카메라와 물체가 튀지 않는다. |

검증을 마치면 작업 ID, 커밋, 빌드 구성, 재현 순서, 관찰 결과를 윤형균과 공유한다. 첫 통합에서는 복도 한 구간에 드론 한 대와 탄환 한 개를 두고 카메라·시간·탄환의 연결을 확인한다.
