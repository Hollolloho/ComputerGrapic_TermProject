# 첫 전투 모듈: 탄환 이동과 첫 충돌

윤형균의 `feature/yoon-combat` 브랜치에서 준비한 탄환 모듈과 사격/포탑 시험장이다. 2026-11-15 친구의 `feature/corridor-test-assets` 기반을 병합했고, 기존 `PlayerCamera::EyePosition()`과 `ViewDirection()`을 발사에 연결했다. 2026-11-16 포탑 경고·적탄·플레이어 체력·실패/승리·재시작을 추가했다. 기본 실행은 드론 1대가 있는 실제 복도 전투이며 F2로 기존 별도 시험장에 전환한다. 무기 파손·버리기·회수·보급은 시험장에 연결했다. 실제 드론 전투·보스와 이동 연동 시간 규칙은 아직 구현하지 않았다.

## 화면에서 실행하기

1. Visual Studio 2026에서 `AEGIS.slnx`를 Debug x64 또는 Release x64로 빌드·실행한다.
2. 기본 화면은 **복도 전투**다. **F2**로 기존 사격 시험장에 전환하고 다시 F2로 복도로 돌아온다.
3. **오른쪽 마우스를 누르고 드래그**해 조준점을 움직이고, **왼쪽 클릭**으로 한 발을 발사한다. 누른 채로는 연사되지 않는다.
4. 청록색 상자가 표적 3개다. 주황색 엄폐물은 중앙 표적 앞을 막는다. **B**로 엄폐물을 끄면 중앙 표적도 맞힐 수 있다.
5. **G**로 총을 버리고, 빈손으로 가까운 총이나 왼쪽 초록 보급대를 바라본 뒤 **E**로 회수·보급한다. 명중하면 총이 깨지므로 남은 표적을 맞히려면 보급을 이용한다.
6. **T**로 포탑 전투/기존 사격장을 전환한다. **R**은 시험장 초기화, **Space**는 일시정지/재개, **Esc**는 종료다. 창 제목에서 상태와 카운터를 확인한다.

## 포탑 전투 실행

기존 포탑 시험장은 기본 실행 → F2 → T, 또는 아래 명령으로 바로 연다.

```powershell
./build/x64/Debug/AEGIS.exe --turret-test
```

- 포탑은 플레이어가 보이면 1초 동안 빨간 센서와 WARNING 표시로 예고하고, 경고 시작 위치를 향해 한 발 발사한다. 발사 후 1.2초 대기한다.
- 적탄은 빨간 큐브, 플레이어 탄은 노란 큐브다. 적탄 속도는 7m/게임초, 플레이어 탄은 12m/게임초인 초기 조정값이다.
- 플레이어 체력은 100, 몸 피격 한 번에 25 감소한다. 적탄은 환경·플레이어 무기·플레이어 몸 중 첫 충돌 하나에서 끝나며 몸 피해가 중복 적용되지 않는다.
- B로 중앙 엄폐물을 켜면 포탑 시야가 가려져 새 사격을 하지 않는다. 발사 경고도 취소된다. 엄폐물에 도달하기 전인 적탄은 벽에 막히며, 이미 벽을 지난 적탄까지 소급 제거하지 않는다.
- 적탄은 발사한 포탑과 충돌하지 않고, 플레이어 탄도 플레이어 자신의 몸을 충돌 목록에 넣지 않는다.
- 포탑 본체를 한 번 맞히면 격파된다. 플레이어 탄이 먼저 본체에 유효타를 낸 프레임은 클리어를 먼저 확정한다. 적 격파 후 새 발사를 막고 이미 발사된 적탄은 계속 처리한다. 적탄이 모두 사라진 뒤 안전 완료로 전환한다.
- 체력 0에서 FAILED와 R RETRY를 표시한다. 실패 후 AI·탄환·사격·엄폐 조작이 멈춘다. R을 누르면 체력·포탑·탄환·쿨다운·피격 효과·카운터·카메라·엄폐물이 초기화된다.
- 초기 엄폐물은 OFF다. 멈춰서 기다리면 네 번 피격돼 실패하는 것을 확인할 수 있다. R 후 바로 중앙 포탑에 사격하면 격파할 수 있다.
- 시험용 영어 픽셀 라벨과 체력 바를 기본 OpenGL 기능으로 표시한다. 최종 한글 UI 구현 완료를 뜻하지 않는다.

`TurretEncounter`는 OpenGL과 독립적인 전투 상태를 관리한다. `Update(realDt, gameDt, eye, forward)`는 외부 시간을 받고, 적탄·경고·대기·피격 효과는 `gameDt`, 플레이어 발사 제한은 `realDt`를 사용한다. 플레이어 몸은 카메라 눈 위치에서 계산한 반경 0.3m/높이 1.8m AABB다. 실제 플레이어 이동·충돌 시스템 연결 시 같은 몸체 기준을 공유해야 한다.

현재 위치는 고정이고 오른쪽 드래그로 조준한다. 시야 검사와 탄환 차단을 보여주기 위한 B 토글은 시험용이며, 최종 게임의 이동·엄폐 조작이 아니다. 포탑 모델은 단순 도형으로 표시하고 드론 모델·복도·부품 계층은 변경하지 않는다.

직접 시험장을 열려면 실행 파일에 `--combat-test`를 전달한다.

```powershell
./build/x64/Debug/AEGIS.exe --combat-test
```

이번 단계는 고정 위치에서 조준·사격하는 계산/화면 연결 시험이다. 복도 에셋은 병합돼 있지만 시험장은 단순 상자로 구성한다. 친구의 복도 렌더링·플레이어 이동 충돌 작업을 대신 구현하거나 완료 표시하지 않는다. 현재 시험장의 게임 시간은 활성 프레임의 실제 시간과 같으며, 이후 공통 시간 계산에서 받은 `gameDt`로 연결한다.

`CombatRange`는 별도 OpenGL 의존 없이 발사 제한(0.25초), 탄환 최대 64개/수명 4초, 표적 파괴, 엄폐물, 재시작 상태를 관리한다. `CombatTestScene`은 이 상태를 표시하고 카메라와 입력을 연결한다. Space·포커스 상실 중에는 입력을 래치만 하고 사격하지 않으며, 복귀 프레임의 눌린 버튼이 새 사격으로 처리되지 않도록 한다.

## 제공하는 기능

- `MakeProjectile`: 월드 시작점과 방향·속도·발사 무기 ID를 받아 탄환 생성. 방향 길이에 관계없이 지정한 속도를 사용한다.
- `FindFirstHit`: 이전 위치에서 새 위치까지 선분과 월드 좌표 AABB의 교차를 검사해 가장 가까운 충돌 하나를 반환한다. 얇은 벽을 한 프레임에 넘어도 검사한다.
- `AdvanceProjectile`: 공용 `gameDt`로 이동하고 첫 충돌점에서 탄환을 비활성화한다. 같은 탄환으로 피해 이벤트를 다시 만들지 않는다.
- 벽·장갑·무기·본체 종류와 대상 ID를 반환한다. 정확히 같은 거리는 벽 → 장갑 → 무기 → 본체 순, 같은 종류는 작은 ID를 우선한다.

## 친구 코드와 연결할 데이터

| 전달 방향 | 데이터 |
|---|---|
| 카메라 → 전투 | 발사 시작점과 바라보는 월드 방향 |
| 시간 → 전투 | 공통 `gameDt`. 전투 안에서 독립적으로 시간 배율을 계산하지 않는다. |
| 장면 → 전투 | 벽·적 몸·무기의 월드 AABB, 고유 ID, 활성 상태 |
| 전투 → 장면 | 첫 충돌 대상·종류·위치와 발사 무기 ID |

```cpp
#include "combat.h"

// 새 클릭을 한 번 감지했고 발사가 허용된 경우에만 생성한다.
auto projectile = aegis::combat::MakeProjectile(
    cameraPosition, cameraForward, bulletSpeed, equippedWeaponId);

// 매 프레임 살아 있는 탄환마다 호출한다.
if (projectile) {
    if (auto hit = aegis::combat::AdvanceProjectile(*projectile, gameDt, colliders)) {
        // hit->kind에 따라 벽 효과 또는 피해를 한 번 처리한다.
        // 명중 시 무기 파손은 sourceWeaponId와 현재 장착 ID를 비교한다.
    }
}
```

위 코드는 API 사용 예시다. 시험장의 탄환 목록·클릭의 눌림 순간·발사 제한은 구현했다. 전체 게임의 발사 성공 시간 신호는 후속 연결한다. 발사자 자신의 몸/무기는 호출자가 충돌 목록에서 제외하고, 적·플레이어 진영 필터도 호출자가 적용한다. 무기와 몸의 실제 첫 경계가 다르면 가까운 경계를 우선하며, 종류 우선순위는 정확히 같은 충돌 거리에서만 적용한다.

현재 범위는 **점 탄환 대 축 정렬 상자**다. 표시용 탄환 큐브의 부피를 충돌 크기로 사용하지 않는다. 회전 물체는 월드 AABB로 감싸야 하고 정밀 메시·회전 상자 충돌은 제공하지 않는다. 움직이는 대상의 프레임 사이 궤적까지 검사하는 연속 충돌은 아직 없다. 시험장에서 빗나간 탄환은 4초 후 목록에서 제거한다.

Visual Studio 2026의 Developer PowerShell에서 저장소 루트를 열고 실행한다.


```powershell

```

40프레임의 확인 화면은 `build/combat-range-smoke.ppm`에 저장한다. 검사용 자동 시나리오는 고정 시간과 프로그램 발사를 사용하므로 마우스/키 입력 검사를 대신하지 않는다. `build/` 결과물은 커밋하지 않는다.

```powershell
./build/x64/Debug/AEGIS.exe --turret-test --smoke-test
```

추가 검증 기록(2026-11-16): Debug/Release 게임 빌드와 각 구성의 47개 순수 검사 통과. Debug/Release 포탑 OpenGL 시나리오에서 경고 → 4회 피격 실패 → 초기화 → 사격 격파를 확인했고, 기존 사격장 OpenGL 시나리오도 통과했다. 실제 창에 키 스캔코드·눌림/해제와 클릭 이벤트를 보내 체력 75, Pause 중 체력 유지, B 엄폐 중 적 발사 없음/플레이어 탄 차단, 체력 0에서 추가 발사 차단, R 체력·카운터 초기화, 직접 사격 클리어, T 사격장/포탑 왕복을 확인했다. 실패·클리어 화면의 체력 바와 재시작 안내도 이미지로 확인했다.

포탑과 플레이어의 피격은 별도 시험장에서 확인한 상태다. 실제 복도·드론 전투와 공통 시간 시스템에 연결되기 전에는 전체 T022/T023 또는 게임 전투 완료를 표시하지 않는다.

## CW-01 C 1인칭 무기 화면

`feature/asset`의 CW-01 C 원본 에셋을 병합했다. 사격장과 포탑 시험장에서 화면 오른쪽 아래에 총을 표시하며, 실제 발사가 승인된 순간에만 반동을 적용한다. 발사 제한·일시정지·실패/클리어 때문에 거부된 클릭은 반동을 만들지 않는다. R 재시작과 시험장 전환은 반동·발사 횟수도 초기화한다. 기존 F2, T, 좌클릭, 오른쪽 드래그 조작을 그대로 사용한다.

`WeaponView`는 `asset/cw01c/runtime/assembly.json`의 배치를 사용해 부품 8개(5,606 삼각형)를 조립한다. 베이스 컬러·노멀·금속도·거칠기·발광 텍스처 5장을 Windows 기본 WIC PNG 디코더로 읽는다. 베이스 컬러는 sRGB, 나머지는 선형 데이터로 취급하고 OpenGL 방향의 노멀 맵을 사용한다. 원본 모델·텍스처는 변경하지 않는다.

런타임 배치 테이블은 아래 명령으로 생성한다. 에셋 배치가 바뀌면 다시 생성하고 헤더도 함께 커밋한다. `--check`는 배치·OBJ 삼각형 수·PNG 크기와 생성 헤더의 일치 여부를 검사한다.

```powershell
python tools/generate_cw01c_layout.py
python tools/generate_cw01c_layout.py --check
```

## 무기 파손·버리기·회수·보급 (2026-11-16)

- 한 번에 한 자루만 장착한다. 빈손 사격, 장착 중 회수/보급, 멀리 있거나 바라보지 않는 총 회수, 벽 너머 상호작용을 차단한다. E/G는 누른 순간 한 번 처리하며 일시정지와 포커스 상실 중에는 작동하지 않는다.
- 적 본체 유효타는 탄환에 기록한 발사 무기 ID와 현재 장착 ID가 같을 때만 총을 파괴한다. 벽 피격·빗나감·적 무기 피격은 플레이어 총을 유지한다. 보급 총은 새 ID, 버렸다 회수한 온전한 총은 기존 ID를 유지한다.
- 적탄은 플레이어의 카메라 방향에 따른 무기 AABB와 몸 AABB 중 첫 충돌 한 곳만 처리한다. 무기 충돌이면 그 총만 깨지고 같은 탄환으로 몸 피해를 주지 않는다. 몸 충돌이면 기존 체력 피해를 적용한다. 무기 충돌은 정밀 메시 대신 보수적인 월드 AABB를 사용한다.
- 포탑 오른쪽의 노란 무기 상자만 맞히면 `DISARMED` 상태가 되어 추가 사격을 멈춘다. 이미 발사한 적탄은 계속 날아간다. 본체를 파괴할 때 무기가 온전하면 한 자루만 떨어지고, 먼저 파손된 무기는 떨어지지 않는다. 사격장의 표적도 온전한 모듈을 하나씩 떨어뜨리는 시험용 대역이다.
- 녹색 보급대는 빈손에게 같은 종류의 총을 한 자루 지급한다. 회수/보급 거리는 시선 방향으로 2.5m다. 총 모델은 보급대와 드롭 위치에도 표시한다. 시험장은 평평한 바닥으로 고정해 버린 총을 즉시 바닥 높이에 놓으며 물리 낙하·던지기는 구현하지 않는다.

`WeaponInventory`는 렌더링과 독립적인 장착·드롭·상호작용 상태다. `CombatRange`와 `TurretEncounter`가 각각 소유하며 `Fire`, `DropWeapon`, `Interact`, `InteractionHint`로 연결한다. 탄환 발사 제한은 버리기/회수/보급으로 우회되지 않는다. 실패 상태에서는 발사·버리기·회수를 차단하고 R로 재시작한다. 클리어 후에도 회수·버리기는 가능하지만 발사는 차단한다.

## T026 구역 완료와 남은 적탄 (2026-11-16)

`Securing` 중에는 새 플레이어 사격을 차단하고 조준·회수·보급을 허용한다. HUD에는 `INCOMING SHOTS / STAY ALERT`, 창 제목에는 `SECURING`, 살아 있는 적탄 수(`Hostiles`), `Analysis: LOCKED`, `Door: 0`을 표시한다. Pause/포커스 상실 시 탄환·완료 처리·문 애니메이션은 멈춘다. 기존 시험장의 B 엄폐 조작은 잔탄 대기 중에도 사용할 수 있다.

적이 없고 적탄 목록도 비면 `Cleared`로 확정하고 남은 플레이어 탄을 정리한다. `CanAnalyze()`가 true가 되며 HUD에 `SECTOR SAFE / ANALYSIS READY`를 표시한다. 이는 후속 분석 단말(T013)의 진입 허용 신호이며 실제 분석 화면이나 단말 조작을 구현한 것은 아니다. 적이 살아 있거나 무기만 파손됐거나 플레이어가 실패한 상태에서는 허용되지 않는다.

복도 문은 안전 완료 뒤 1게임초 동안 좌우 1.45m씩 미끄러져 열린다. 이동 거리는 원본 매니페스트에서 생성하며 렌더 모델과 문짝 충돌 AABB가 같은 `DoorProgress()`를 사용한다. R/F2/F3 초기화는 적·탄환·무기뿐 아니라 완료 상태·분석 허용·문 열림 진행도·닫힌 문 충돌도 복원한다. 출구로 걸어가는 플레이어 이동과 다음 구역 전환은 후속 작업이다.

순수 검사는 135개다. 격파 후 적탄 유지와 피해, 잔탄 대기 중 Pause, 격파 뒤 치명타 시 실패 우선, 빗나간 적탄 만료, 안전 완료 허용, 문 개방과 충돌 해제, 문 Pause·재시작을 추가했다. 드론 OpenGL 시나리오는 1320 고정 프레임으로 늘려 실패 → 초기화 → 적 발사 후 격파 → 잔탄 대기 → 플레이어 25 피해 → 안전 완료·문 완전 개방까지 검사한다. `build/sector-securing-smoke.ppm`과 `build/sector-open-smoke.ppm`에 확인 화면을 저장한다. 이전 드론 시나리오의 1080프레임·격파 직후 적탄 정리 기준은 이 규칙으로 대체한다.

## T013 분석 단말 E 상호작용 (2026-11-16)

작업 전에 원격을 확인했으며 친구의 마지막 에셋 커밋은 `3e60203`으로 추가 변경이 없었다. 해당 브랜치를 병합해 분석 단말·보급대·수정탄·진입실·코어실·보스 에셋을 받았고, 이번 구현에서는 분석 단말만 새로 장면에 연결했다. 다른 방·보스·보급대의 새 모델은 가져온 상태이며 이번 작업의 구현 완료 항목이 아니다.

복도 시작점 기준 오른쪽 `(0.95,0,-1.5)`에 실제 단말 OBJ/MTL을 배치한다. `assembly.json`의 경계와 상호작용 지점을 공유 헤더로 생성해 표시·탄환 차단·E 대상 판정에 사용한다. `tools/generate_terminal_layout.py --check`는 원본 단위·방향·경계·3564 삼각형·헤더 일치를 확인한다.

- 2.5m 안에서 단말을 바라보면 안전 상태에 따라 `E ANALYZE DRONE` 또는 잠금 안내를 표시한다. 적 또는 적탄이 남았거나 실패한 상태에서는 E를 눌러도 열리지 않는다. 현재 복도의 안전 완료 상태를 사용하며 진입실 장면의 안전 구역 판정은 그 장면을 연결할 때 제공한다.
- E는 가장 가까운 선택 대상 하나만 처리한다. 무기 회수/보급과 단말이 같은 광선에 겹치면 거리로 선택하고, 벽 너머 대상은 제외한다. 단말이 선택된 상태에서 잠겼다고 뒤의 무기 상호작용으로 넘어가지 않는다. E를 누른 채로 안전해지거나 진입한 경우에도 중복 진입/즉시 종료하지 않는다.
- 분석 중에는 세계 업데이트·사격·버리기·보급·월드 조준·F3 적 전환을 막는다. 문 진행도와 세계 효과도 정지한다. Space는 별도 Pause를 켜지 않으며 E 또는 Esc로 분석을 닫는다. 분석 밖의 Esc는 기존대로 종료한다. 포커스 상실 중에는 E 입력을 소비하지 않고 복귀 시 눌린 입력을 새 조작으로 취급하지 않도록 기존 입력 래치를 유지한다.
- 현재 분석 화면은 별도 배경과 고정 시점의 드론 미리보기다. 공유 모델 메시를 쓰되 파괴된 전투 드론의 상태를 바꾸지 않고 온전한 고정 자세로 표시한다. 플레이어 위치·yaw·pitch는 진입 중 변경하지 않으므로 닫으면 같은 시점으로 복귀한다. 이 작업은 공전·휠 확대를 구현하지 않는다.
- R과 F2는 분석을 닫고 기존 전투/모드 초기화를 수행한다. 진입/종료 신호는 단조 증가하는 리비전이라 재시작에서 숫자를 0으로 되돌리지 않는다. 따라서 카메라·시간 담당자가 초기화로 인한 종료도 누락 없이 관찰할 수 있다.

카메라·시간 통합 API: `GameScene::AnalysisActive()`로 세계 정지와 입력 분기를 확인하고 `GameScene::AnalysisState().Entries()`/`Exits()`의 마지막 관찰 값과 비교해 진입·종료를 한 번씩 처리한다. `CloseAnalysis()`는 열려 있을 때만 닫고 true를 반환한다. 현재 분석 입력/정지 처리는 `CombatTestScene`에 있으며, 친구의 T014~T016 공전 카메라·FOV·커서 복원 코드가 이 상태에 연결되도록 구성했다.

순수 검사는 153개다. 거리·조준·벽 가림·가까운 무기 우선·안전 상태·살아 있는 적과 남은 적탄 차단·중복 진입/종료 방지·초기화 종료 신호 등을 추가했다. 드론 OpenGL 시나리오에서는 문이 일부 열린 상태에서 분석에 진입해 문 진행도가 멈췄는지 확인하고, 분석 종료 후 세계로 돌아와 문이 완전히 열리는지 검사한다. `build/analysis-terminal-smoke.ppm`에 고정 미리보기 화면을 저장한다.

## T030/T031 코어실 보스 전투 시험 (2026-11-17)

친구가 제공한 `asset/core_room/runtime/placement.json`과 `asset/boss_e/runtime/assembly.json`을 그대로 기준으로 코어실 로컬 좌표에 보스를 배치한다. 기본 드론 전투와 기존 시험장을 유지하고 F4로 보스 시험을 전환한다. `--boss-test`로 바로 실행할 수 있다. 코어실은 별도 전투 장면이며 아직 복도 출구를 걸어서 통과하는 진행에 연결하지 않았다.

보스는 경고 1.2 → 양쪽 포탑 발사/공격 0.35 → 장갑 개방 0.75 → 약점 노출 3 → 장갑 폐쇄 0.6 → 회복 1.2게임초를 반복한다. 경고 중 몸 중심을 조준하며 포탑은 원본 제한인 yaw ±25°, pitch -10~35°로 회전한다. 실제 총구 위치와 방향에서 속도 7m/게임초의 두 탄환을 발사한다. 방·엄폐물로 시야가 막힌 포탑은 발사하지 않고, 이미 발사된 탄환은 기존 선분 대 AABB 규칙으로 환경·플레이어 무기·몸 중 한 곳만 처리한다. 몸 피격은 탄환당 25 피해다.

- 장갑은 각자 X축 ±0.555m 이동한다. 완전히 열린 단계에서만 코어가 Body 약점이 된다. 닫힘·전환·폐쇄 단계에는 약점 위치를 Armor로 보호한다. 첫 유효타가 들어오는 즉시 노출 단계를 끝내므로, 같은 개방에 여러 탄환이 도착해도 1회만 인정한다. 폐쇄 애니메이션이 아직 진행 중이어도 추가 피해를 허용하지 않는다.
- 정확히 3회의 별도 개방 유효타로 보스를 격파한다. 마지막 유효타 뒤 남은 적탄이 있으면 Securing으로 처리하고, 적탄이 정리된 뒤 Victory로 확정한다. 남은 탄환에 체력이 0이 되면 실패가 우선한다. 승리 후 피해와 격파가 중복되지 않는다.
- 유효타는 탄환의 발사 무기 ID와 현재 장착 ID가 같을 때만 총을 깨뜨린다. 장갑·벽·빗나감은 총을 유지한다. 새로 보급받은 총을 이전 탄환이 깨뜨리지 않는다. 보스 자체는 일반 적 무기 드롭을 만들지 않는다.
- 보급대·좌우 엄폐물은 원본 코어실 배치를 사용한다. 이동 코드 통합 전의 B는 `(0,0,-2.4)` 사격 위치와 `(2.72,0,-4.05)` 엄폐/보급 위치를 오가는 시험용 프리셋이다. 보급 위치로 바꿀 때 보급대를 향해 시점을 설정하고 E로 한 자루를 받는다. 사격 위치로 돌아올 때 코어를 향하도록 설정한다. 실제 WASD나 보편적인 엄폐 이동 기능으로 완료 표시하지 않는다.
- R은 체력·코어 유효타·장갑·공격 단계·발사/피격 타이머·무기·드롭·탄환·시험 위치·카메라·HUD를 초기화한다. 실패/승리 이후 추가 사격은 막는다. Pause/포커스 상실 중에는 보스 패턴·탄환·장갑이 멈춘다.

`generate_boss_layout.py`는 14개 OBJ의 삼각형 수와 조립 부모 순서·좌표/단위·텍스처 경로·원본 약점 치수·방 충돌을 검증해 `boss_layout.generated.h`와 `boss_triangles.generated.inc`를 만든다. 약점은 원본 core_visual 아래의 중심/반범위를 사용한다. 본체를 큰 AABB로 감싸면 노출된 코어까지 막히므로 각 부품의 로컬 AABB를 먼저 검사하고 실제 부품 삼각형과의 가장 가까운 교차를 계산한다. 렌더와 충돌은 같은 장갑 이동·포탑 회전 행렬을 사용한다.

무기와 보스의 5맵 렌더링은 공용 `AtlasModel`로 분리했다. 기존 무기의 시점·반동·발사 횟수 API는 유지한다. 보스 베이스 컬러와 발광 텍스처는 sRGB로 읽고 노멀·금속도·거칠기는 선형으로 읽는다. 발광 배율 2.55와 경고/코어 부품별 발광을 적용하며, 2048 원본 아틀라스와 원본 모델은 변경하지 않는다.

검사는 178개다. 실제 기하의 닫힌 장갑 차단·열린 코어 노출·폐쇄 중 추가 피해 차단, 예고와 두 발 발사, 엄폐, 느린 gameDt와 Pause, 개방당 한 번 유효타, 보급 2회 후 3회 유효타 승리, 이전 무기 ID 보호, 마지막 적탄 정리 대기, 실패·재시작을 포함한다.

현재 단계는 보스 전투 시험이다. T032 세 구역 진행, T033 시작/한글 안내/결과 메뉴, 친구의 이동·공통 시간·카메라 시스템 및 T046 파편 연출의 전체 통합 완료를 뜻하지 않는다.

## T032/T033 캠페인 순서와 한글 메뉴 (2026-11-17)

기본 실행은 이제 한글 시작 화면이다. 기존 개별 시험장은 `--drone-test`, `--boss-test`, `--corridor-test`, `--combat-test`, `--turret-test`로 유지한다. 캠페인 실행과 자동 검사는 `--campaign-test [--smoke-test]`를 사용한다. 캠페인에서는 F2/F3/F4/T 시험 전환을 막아 진입실→복도→보스 순서를 건너뛰지 못하게 한다.

`CampaignFlow`는 OpenGL과 독립적인 시작·안내·플레이·일시정지·실패·승리 상태와 Entry/Corridor/Boss 체크포인트를 관리한다. `GameScene`이 실제 모델·전투·메뉴 버튼을 연결한다. 새 구역과 해당 구역 재시작은 체력 100·기본 총·적/보스·탄환·문·카메라를 기준 상태로 복원한다. 구역 전환에 이전 적탄이나 빈손 상태를 넘기지 않는다.

- 시작 화면: 게임 시작·조작 안내·게임 종료 버튼. Enter는 기본 버튼 한 번만 실행한다.
- 안전 진입실: 친구의 실제 진입실 모델과 원본 시작점을 사용하고, 접합된 복도를 함께 그린다. 안전 진입실에서는 적과 세계가 진행하지 않는다. `복도로 진입` 버튼/Enter로 전투를 시작한다.
- 전투 복도: 드론 전투·잔탄 처리·문 개방·안전한 분석 단말은 기존 기능을 사용한다. 적/적탄이 남았거나 문이 여는 중이면 `코어실로 이동` 버튼을 비활성화한다. 안전하고 문이 완전히 열린 뒤에만 다음 구역을 허용한다. 분석 중에는 진입 버튼을 숨기고 E/Esc 복귀를 우선한다.
- 코어실: 보스 약점 유효타 3회·남은 적탄 정리가 끝나면 최종 `작전 성공` 화면으로 이동한다. 보스전의 B는 기존 시험용 사격/엄폐 위치 프리셋을 유지한다.
- 일시정지: Esc 또는 Space로 열고 계속하기·현재 구역 다시 시작·시작 화면·게임 종료를 선택한다. 메뉴/UI 입력은 계속 받고 전투·탄환·장갑·문 시간은 멈춘다. 분석 중 Esc는 분석 종료가 우선이고 Space는 별도 Pause를 켜지 않는다.
- 실패: 현재 구역 다시 시작·시작 화면·게임 종료를 명시적으로 선택한다. 복도에서 실패하면 복도, 보스에서 실패하면 보스부터 재시작한다. R/Enter도 현재 구역을 다시 시작한다.
- 최종 승리: 처음부터 다시 시작·시작 화면·게임 종료를 선택한다. 다시 시작은 안전 진입실로 돌아간다. 캠페인 결과 메뉴에서는 기존 영문 시험용 결과 HUD를 숨긴다.

한글 UI는 Windows GDI의 `Malgun Gothic`을 현재 창 크기에 맞게 래스터화해 OpenGL RGBA 텍스처로 그린다. 색·버튼·호버·사용 가능 상태·한글 줄바꿈을 처리하고 페이지/크기/호버가 바뀔 때만 텍스처를 갱신한다. 시스템 글꼴을 사용하므로 별도 글꼴 파일을 저장소에 배포하지 않는다. Windows 기본 GDI/User32 라이브러리를 링크한다.

마우스 위치는 창 좌표를 UI 논리 좌표로 정규화해 DPI/프레임버퍼 크기와 분리한다. 버튼/메뉴 클릭과 Enter는 한 번만 처리하고 그 프레임의 전투 입력을 래치하여 UI 클릭이 총알로 새어 나가지 않게 한다. 단순히 HUD 위에 커서가 있다는 이유로 E/B/조준을 막지 않는다. 창 포커스 상실 중에는 기존처럼 세계를 멈추고 입력을 새 클릭으로 취급하지 않는다.

진입실 배치 헤더는 `tools/generate_campaign_layout.py`가 원본 `asset/entry_room/runtime/placement.json`의 단위·3812 삼각형·플레이어 시작점·단말 배치를 검증해 만든다. 아직 구역 사이를 걸어서 통과하는 이동 판정은 없으며 현재는 명시적 진입 버튼을 사용한다. 이동·시설 충돌·시간 배율·분석 공전 카메라의 완전한 통합이나 T032/T034 전체 완료로 표시하지 않는다.

순수 검사는 201개다. 캠페인 순서·안전 조건·Pause·체크포인트·실패 우선·최종 승리 1회·처음부터 재시작을 추가했다. `--campaign-test --smoke-test`는 안내·시작·진입실·복도 Pause·사망·재시작·복도 완료·보스전·최종 승리·처음부터 재시작·시작 화면 복귀를 실행한다. `build/campaign-title-smoke.ppm`, `campaign-help-smoke.ppm`, `campaign-entry-smoke.ppm`, `campaign-paused-smoke.ppm`, `campaign-failed-smoke.ppm`, `campaign-victory-smoke.ppm`에 한글 화면을 저장한다.

캠페인 최종 검증(2026-11-17): Debug/Release 게임 빌드와 각 구성 201개 순수 검사, 두 구성의 캠페인·보스·드론·복도 포탑·사격장·별도 포탑 OpenGL 시나리오가 통과했다. 실제 버튼/키 입력으로 두 체크포인트 재시작부터 최종 승리·처음부터 재시작·종료 코드 0까지 확인했다. 한글 시작·안내·진입실·Pause·실패·승리 화면을 시각 확인했고, 진입실 생성 데이터 검사도 통과했다.


## 한글 전투 HUD (2026-11-17)

캠페인 상단에 체력 수치·체력 바·무기 장착/빈손·누적 파손 수를 표시하고, 보스전에서는 코어 명중 0/3~3/3을 함께 표시한다. 드론 순찰·조준 예고·사격 후 대기·무장 해제, 보스 사격 예고·장갑 개폐·약점 노출, 적 파괴 후 잔여 적탄·문 개방·안전 확보에 맞춰 목표와 경고를 갱신한다. 빈손일 때는 실제 조준 상호작용에 따라 E 보급/회수를 안내한다. 보스의 엄폐/사격 위치에 따라 B 안내도 달라진다.

기존 영문 개발 HUD는 명시적 시험 모드에서 유지하고 캠페인에서는 한글 HUD로 대체한다. 분석 화면은 기존 전용 화면을 유지한다. 경고는 주황색, 체력 바는 체력 25 이하에서만 주황색이며 화면 메뉴에는 전투 HUD를 표시하지 않는다.

검증: Debug·Release 빌드와 캠페인 자동 완주, 기존 전투 검사 201개, 실제 입력으로 메뉴·중복 사격 차단·양 구역 재시작·두 차례 보급·보스 3회 명중·승리 재시작·종료를 확인했다. build/campaign-corridor-hud.ppm, campaign-boss-hud.ppm, campaign-empty-hud.ppm은 자동 시험에서 생성되는 화면 검토용 캡처이며 버전 관리에서 제외한다.


## 피격 플래시와 플레이어 무기 파손 효과 (2026-11-17)

체력 감소를 관찰하면 화면 가장자리에 0.28 게임초 동안 서서히 사라지는 붉은 반투명 띠를 표시한다. 조준점과 한글 HUD는 유지한다. 무기 인벤토리의 확정된 파손 횟수가 증가할 때만 현재 플레이어 총 위치 부근에서 금속색 파편 18개를 한 번 발생시킨다. 단순 사격·빗맞힘·총 내려놓기·보급·같은 상태 재조회는 추가 파손 효과를 만들지 않는다. 파편은 장식용 기본 도형이며 무기 회수 대상이나 피해 판정을 만들지 않는다.

CombatFeedback은 전투 상태를 변경하지 않는 표시 전용 상태다. 파편 이동·중력·회전·축소와 피격 효과 수명은 gameDt를 따른다. Pause·포커스 상실·분석 화면에서는 기존 세계 업데이트 차단에 따라 효과도 정지한다. 구역 재시작·모드 전환·다음 구역·타이틀 복귀 시 Reset으로 파편·플래시·관찰 카운터를 함께 비운다. 동시 파편은 최대 18개로 제한한다.

검증: 효과 수명·중복 발생 차단·느린 시간·0시간·잘못된 시간·프레임 분할에 따른 이동 일치·재시작 초기화 검사를 포함한 전투 검사 214개. Debug에서 캠페인·보스·드론·사격장 자동 검증, Release 빌드·검사·캠페인 완주 확인. 자동 시험에서 실제 파손 수와 효과 발생 수를 비교한다. build/campaign-damage-effect.ppm과 build/campaign-weapon-break.ppm으로 실제 피격·파손 화면을 검토했다.

이번 범위는 플레이어 피격과 장착 무기 파손 표현이다. 적 부품 비산·플레이어 사망 파편·친구 담당 탄환 비행 효과와 합친 T046 전체 완료로 표시하지 않는다.


## SUPERHOT식 시간 전투 연결 준비 (2026-11-17)

전투 진입점은 `GameScene::Update(realDt, baseGameDt)`로 분리했다. 이동 담당은 벽 충돌 후 실제 변위로 계산한 배율을 `baseGameDt = realDt * movementScale`로 전달하면 된다. 현재 프레임워크에서는 친구 코드 연결 전이므로 `PreviewTimeScale()`의 수동 배율을 대신 전달한다. 입력은 F5로 1배/0.05배 전환, Shift를 누르는 동안 정상 진행이다. 키를 누르고 있어도 F5 배율이 반복 전환되지 않는다. 화면에는 수동 시험·현재 배율·이동 연동 전을 명시한다. WASD·카메라 회전으로 이동량을 흉내 내어 배율을 계산하지 않는다.

`CombatTime`은 이 입력에 사격 진행만 더한다. Fire가 실제로 성공한 경우 0.25초 정상 진행을 예약하며 중복 발사는 막는다. 빈손·잘못된 방향·사격 제한으로 거부된 발사는 진행을 예약하지 않는다. 구간 경계 프레임은 남은 정상 진행 시간과 기본 배율 구간으로 나눠 계산한다. 예를 들어 0.05배에서 진행 시간이 0.15초 남은 상태로 0.2초 업데이트하면 gameDt는 0.15 + 0.05*0.05 = 0.1525초다. 마우스 조준·무기 반동은 실제 시간, 적·탄환·보스·문·파손 효과는 최종 게임 시간을 사용한다.

Pause·포커스 상실·분석에서는 세계 업데이트를 차단하므로 사격 진행·기존 사격 쿨다운도 소모하지 않는다. 명시적으로 baseGameDt=0을 전달해도 실제 시간/게임 시간을 모두 0으로 전달해 전투를 멈춘다. 이 값은 정지 신호이며, SUPERHOT식 서 있는 상태는 0이 아닌 0.05배로 전달해야 한다. 재시작·구역 변경은 진행 타이머와 수동 시험 배율을 함께 초기화한다.

친구의 공통 시간 코드가 사격/Shift까지 담당하게 되면 이 임시 브리지를 공통 시간 계산 위치로 옮겨 최종 gameDt를 한 번만 계산해야 한다. 이미 사격 보정을 마친 gameDt에 이 브리지를 중복 적용하지 않는다. 현재 `TestScene().TimeState()`로 진행 잔여 시간과 마지막 유효 배율을 조회할 수 있다. 창 제목의 TimeBase/TimeScale/ShotWindow는 입력 시험용 값이다.

검증: Debug·Release 빌드와 각 구성 전투 검사 230개 통과. 30/60/144fps에서 1초 중 사격 0.25초 + 느린 시간 0.75초의 총 gameDt 0.2875초가 일치하며, 실제 탄환 이동도 검사한다. 기존 Debug 캠페인·보스·드론·사격장 시나리오와 Release 캠페인 완주 통과. 실제 Windows 게임 입력에서 F5 길게 누르기, Shift 눌림/해제, 발사 후 정상 진행 및 복귀, 진행 도중 Pause의 잔여 타이머 유지, 버튼 길게 누름으로 재발사되지 않음, 두 번째 사격, R 초기화·종료를 확인했다.

범위: 시간 기반 전투의 수신·사격 진행·수동 시험 준비다. 이동·시설 충돌과 실제 변위 배율의 T019, 공통 시간 소유권 통합과 전체 T028 완료를 뜻하지 않는다.
