# AEGIS 저항 작전

가제. 중앙 AI가 장악한 미래 시설에 인간 저항군이 침투하는 OpenGL 3D 1인칭 전술 액션 게임이다. SUPERHOT의 움직임에 연동되는 시간 규칙을 참고하며, 제작한 감시 드론과 복도 에셋으로 전투 구역과 중앙 AI 보스전을 완성한다.

## 브랜치 기준

- `main`은 공용 기획과 통합 기준이다. 기본 게임 솔루션 `AEGIS.slnx`, 실행 코드, 공용 라이브러리, Assimp 로더가 들어 있다.
- `codex/t006-corridor`에서 복도 시험 장면과 드론·카메라 연결을 관리한다. `feature/asset`에서 게임용 모델과 재질을, `feature/yoon-combat`에서 전투 구현을 관리한다.
- 공용 브랜치로 PR을 열 때 기준은 `main`이다. 기능 브랜치의 구현이나 에셋이 필요한 작업은 사용할 브랜치와 커밋을 먼저 확인한다.

## 빌드와 실행

Visual Studio에서 [AEGIS.slnx](AEGIS.slnx)를 열고 MSVC `v145`, Windows SDK `10.0` 환경에서 `Debug | x64` 또는 `Release | x64`로 빌드한다. 게임 소스는 `game/src/`에 있고, [공용 라이브러리](external/README.md)는 솔루션 옆의 `external/`에 있다. 경로는 `$(SolutionDir)`를 기준으로 찾고 GLEW·Assimp DLL은 빌드할 때 실행 파일 옆으로 복사한다.

저장소 루트에서 `build/x64/Debug/AEGIS.exe` 또는 `build/x64/Release/AEGIS.exe`를 실행하면 **한글 시작 화면**이 열린다. 게임 시작 → 안전 진입실 → 전투 복도 → 코어실 보스전 → 최종 결과 순으로 진행한다. 버튼이나 Enter로 구역에 진입하며 복도는 적·적탄이 사라지고 문이 완전히 열린 뒤에만 다음 구역을 허용한다. 실패하면 현재 구역 재시작, 승리하면 처음부터 다시 시작·시작 화면·종료를 선택한다. Esc/Space는 캠페인 일시정지 메뉴, R은 현재 구역 재시작이다.

전투 중 **F5**로 시험용 시간 배율을 1배 ↔ 0.05배로 바꾼다. **Shift**를 누르는 동안에는 정상 속도로 진행하며, 사격이 실제로 성공하면 **0.25초의 실제 시간 동안 세계가 정상 속도로 진행**한다. 그동안 추가 사격은 막는다. Pause·포커스 상실·분석 화면에서는 이 진행 시간도 멈추고, R/구역 재시작 시 시험 배율은 1배로 돌아간다. 이는 수동 배율 시험이며 **WASD 이동량에 따른 자동 시간 조절은 아직 연결 전**이다.

아래 설명의 F2/F3/F4는 **별도 시험 옵션으로 실행했을 때만** 사용한다. 기본 캠페인에서는 구역 순서를 건너뛰지 못하도록 비활성화한다. `--drone-test`, `--boss-test` 등은 기존 시험 장면을 직접 여는 옵션이다.

별도 시험 모드 설명:  이 전투 브랜치의 기본 화면은 친구의 실제 복도에 순찰 드론 1대를 연결한 전투 장면이다. 드론은 순찰 → 조준 예고(빨간 센서) → 한 발 발사 → 대기를 반복한다. 마지막 적을 잡아도 날아오던 적탄은 남아 피해를 줄 수 있다. 적과 적탄이 모두 없어져 안전해지면 구역 완료가 되고 출구 문이 열린다. F3로 기존 고정 포탑 전투와 전환한다. 오른쪽 드래그로 조준하고 좌클릭으로 사격한다. G는 무기 버리기, E는 가까운 무기 회수·왼쪽 녹색 보급대 이용, R은 전투·무기·카메라 전체 초기화다. Space는 일시정지/재개, Esc는 종료다.

F2는 복도 전투와 기존 시험장을 왕복한다. 기존 시험장에서 T로 사격장/포탑 시험장을 바꾼다. 복도의 벽·바닥·천장·엄폐물·닫힌 문은 탄환을 차단한다. 현재 플레이어 위치는 고정이며 WASD 이동·플레이어 시설 충돌·이동 연동 시간은 아직 연결하지 않았다. 드론의 순찰·조준·대기·팬 회전과 탄환은 전달받은 게임 시간으로 진행한다. 실행·무기 규칙과 검증 방법은 [전투 통합 문서](docs/COMBAT_INTEGRATION.md)를 참고한다.

`--inspect-obj`는 Assimp로 OBJ와 연결된 MTL을 읽어 메시·삼각형 수와 재질 정보를 출력한다.

```powershell
& .\build\x64\Debug\AEGIS.exe --inspect-obj .\asset\corridor\test_scene\corridor_static.obj
py -3 tools/check_corridor_test_assets.py
```

## T006 복도 렌더링과 전투 연결

복도, 문틀, 좌우 문짝, 엄폐물의 OBJ 5개를 미터 단위 그대로 그린다. 문틀은 `(0, 0, -17.81)`, 좌우 문짝은 문틀 기준 X축 `±0.72`에 닫힌 상태로 배치한다. 엄폐물은 `(-1.2, 0, -8.4)`에서 Y축으로 90도 회전한다. 렌더 배치와 닫힌 문 충돌 경계는 `python tools/generate_corridor_layout.py`로 생성하며 `--check`로 원본과 일치를 검사한다. 닫힌 두 문짝의 중앙 4cm 시각적 틈은 점 탄환 통과를 막도록 충돌 경계에서 닫는다. 배치는 [장면 매니페스트](asset/corridor/test_scene/scene_manifest.json)를 따르며, [에셋 검사 스크립트](tools/check_corridor_test_assets.py)로 OBJ 구조와 매니페스트를 확인할 수 있다.

복도는 MTL의 `Kd`를 기본색으로 사용한다. `Ks`는 0~1 범위로 제한해 유전체의 정면 반사율(F0)로 사용하고, `Ns`는 `sqrt(2 / (Ns + 2))`로 거칠기를 근사한다. 드론은 자체 재질의 금속성과 거칠기를 사용한다. 현재 두 모델 모두 불투명하게 그리며, 이미지 텍스처와 노멀맵은 후속 연결 항목이다.

## 작업 원칙

- 기획은 프로젝트 기획서, 실제 완료는 TASKS, 제출 문서는 DOCX와 PDF에서 관리한다. 같은 목적의 요약본을 추가하지 않는다.
- 문서와 제안서가 달라지면 최신 사용자 결정을 우선하고 해당 기준 문서와 제출본을 함께 맞춘다.
- 카메라 확대·이동·자전·공전·부모 관계는 모두 필수다.
- 시간 전투·중앙 AI 보스·결과·재시작까지 연결한 뒤 선택 표현을 추가한다.
- 문서 작성이나 컴파일만으로 구현 완료를 체크하지 않는다.
- 잔향은 겨울방학 프로젝트로 보류하며 현재 게임의 작업과 섞지 않는다. 보관본 원문은 변경하지 않는다.

다른 AI도 이 README에서 시작하면 된다. 문서 기준일은 2026-11-10이다. 현재 기획서의 초기 조정값은 전투 시제품에서 확인할 초안이며, 제출 일정은 기존 수업 안내를 기준으로 유지하고 변경 공지를 우선한다.


## 드론 행동 검사

`--drone-test --smoke-test`는 실제 복도에서 순찰·예고·사격·플레이어 실패 → 초기화 → 드론 격파·무기 파손·드롭을 검사한다. `--corridor-test`는 기존 복도 포탑, `--combat-test`와 `--turret-test`는 기존 별도 시험장을 유지한다. 각 옵션 뒤에 `--smoke-test`를 붙이면 자동 검사 후 종료한다.


구역 완료 상태는 전투 중 → 적탄 잔여 대기(`SECURING`) → 안전 완료(`CLEARED`)로 나뉜다. 분석 허용 여부는 안전 완료에서만 READY가 된다. 오른쪽 아래의 분석 단말을 바라보고 E로 열면 고정된 드론 미리보기를 볼 수 있다. 분석 중 세계와 전투 입력은 멈추며 E 또는 Esc로 원래 시점에 복귀한다. 공전·확대 카메라는 후속 연결이다. 출구 문 모델과 충돌은 같은 진행도로 1게임초 동안 열리고, R로 재시작하면 닫힌 상태로 복원된다.


분석 단말은 친구의 `feature/asset` 커밋 `3e60203`에 포함된 OBJ를 사용한다. `python tools/generate_terminal_layout.py --check`로 원본 메타데이터·삼각형 수·공유 배치 헤더를 검사한다. 분석 진입/종료 상태는 `GameScene::AnalysisActive()`와 `AnalysisState().Entries()/Exits()`로 카메라·시간 담당 코드에 전달한다.


## 코어실 보스 시험

별도 시험은 `AEGIS.exe --boss-test`로 바로 열거나, `--drone-test`에서 **F4**로 코어실 보스전/복도를 전환한다. 오른쪽 드래그로 조준하고 좌클릭으로 사격한다. 빨간 경고와 양쪽 포탑 발사 뒤 장갑이 열리면 청록색 코어를 맞힌다. 열린 시간당 유효타 1회, 총 3회로 승리한다. 닫힌 장갑은 탄환을 막으며 총을 소모하지 않는다. 약점 명중은 발사 무기 ID가 일치하는 장착 총을 파괴한다.

플레이어 이동 연결 전 시험을 위해 **B**는 사격 위치와 엄폐·보급 위치를 전환한다. 엄폐 위치에서는 보급대를 향하므로 빈손일 때 **E**로 재무장한다. **R**은 보스·장갑·체력·무기·탄환·시점을 초기화하고 Space는 일시정지다. 실제 WASD 이동과 진입실→복도→코어실의 진행은 후속 통합 항목이다.

```powershell
python tools/generate_boss_layout.py --check
./build/x64/Debug/AEGIS.exe --boss-test --smoke-test
```

보스는 원본 14개 부품, 3184 삼각형, 텍스처 5장을 사용한다. 같은 리그 변환으로 장갑·포탑·약점 표시와 부품 삼각형 충돌을 계산한다. 자동 시나리오는 실패·재시작·닫힌 장갑 차단·엄폐/보급·세 번의 약점 명중·승리를 확인한다.


## 캠페인·한글 메뉴 검사

Windows 기본 맑은 고딕을 GDI로 래스터화하고 OpenGL UI 텍스처로 표시한다. 글꼴 파일이나 외부 UI 패키지를 추가하지 않는다. 시작·조작 안내·일시정지·구역 진입·실패·최종 승리 화면을 한글로 제공하고 버튼은 마우스와 Enter로 조작한다. 메뉴 클릭을 전투 사격으로 전달하지 않는다.

```powershell
python tools/generate_campaign_layout.py --check
./build/x64/Debug/AEGIS.exe --campaign-test --smoke-test
```

자동 시나리오는 안내 화면·시작·진입실·복도 Pause·실패·체크포인트 재시작·복도 완료·보스 격파·최종 승리·처음부터 다시 시작·시작 화면 복귀를 검사한다. 실제 이동·플레이어 시설 충돌·이동 연동 시간·분석 공전 카메라는 친구 코드와 후속 통합한다. 현재 구역 전환은 버튼 방식이다.
