# 《내일도 와줄 거지》 초소형 단계 구현 체크리스트

- 버전: 1.1 / 작성일: 2026-09-30 / 카메라 점검 추가: 2026-10-01
- 전체 계획: [GAME_DEVELOPMENT_PIPELINE.md](GAME_DEVELOPMENT_PIPELINE.md)
- 게임 기획: [GAME_DESIGN_DRAFT.md](GAME_DESIGN_DRAFT.md)
- 이 문서는 **한 줄을 구현하고 직접 확인한 다음 다음 줄로 넘어가는 작업 목록**이다. 아직 완료된 항목은 없다.

## 사용 방법

1. 오늘 할 일은 표의 한 항목만 골라 시작한다. 해당 항목의 선행 ID가 완료되어 있어야 한다.
2. `구현`에는 한 가지 변경만 적었다. `완료 화면·확인`을 만족하면 상태를 `[x]`로 바꾼다.
3. 번호는 전반적인 진행 순서다. 선행 조건이 충족되면 B는 사건·대사 작업을 A의 그래픽 작업과 별도로 진행할 수 있다.
4. 작은 항목도 학습 때문에 오래 걸릴 수 있다. 60~90분 이상 원인을 모른 채 막히면 새 기능을 더하지 말고 오류 메시지·예상 결과·실제 결과를 적어 함께 확인한다. 이 시간은 작업 소요를 보장하는 추정치가 아니다.
5. 표의 `공동` 작업은 두 사람이 같은 실행 화면을 보고 한 번 맞추는 작업이다. A는 C++ 4/10, B는 C++ 2/10인 개발자를 뜻한다.
6. 한 항목이 너무 크면 같은 ID 아래 `a/b/c`로 더 나눈다. 빌드가 깨진 상태로 여러 항목을 진행하지 않는다.
7. 폴더·클래스 이름은 권장안이다. 항목을 위해 빈 클래스 수십 개를 먼저 만들지 않는다.

코드 변경 항목마다 **빌드 → 실행 → 표에 적힌 동작 확인**을 한다. 문서 항목은 실제 사실과 추론이 일치하는지 읽어서 확인한다. 완료 기준에 적힌 개발용 텍스트·단축키는 최종 UI가 아니며 마지막에 정리한다.

K001~K004는 기존 이동·시점 기능을 부모 구조로 정리하는 작업이다. 공전 상세보기 K005~K011은 새 후보 기능이므로 핵심 잔향 퍼즐을 먼저 완성한 뒤 추가 여부를 결정한다. 현재 작업 목표에 채택하지 않았다면 `보류`로 표시한다.

## 일정이 부족할 때 지킬 순서

1. 끝까지 플레이되는 사건과 첫 잔향 시야 퍼즐을 지킨다.
2. 안개·흡입은 가장 단순한 화면 효과로 유지한다.
3. 추가 잔향, 카메라 실제 전진, 외부 모델, 환경 장식 순으로 보류한다.
4. 한글 가독성, 벽 충돌, 복귀 위치, 증거의 논리는 축소하지 않는다.
5. 체크 항목을 많이 끝낸 것보다 하나의 퍼즐을 설명 없이 플레이할 수 있는지가 중요하다.
