# 일정·분업·축소 규칙

각자 2~3시간, 주 5일로 답변을 받았다. 작업일은 달력 날짜가 아닌 실제 개발 가능한 날이다.

## 왜 3주 기준인가

OpenGL 학습과 한글/UI 연결이 동시에 필요하다. 계획시간은 A 약 24~28시간, B 약 18~24시간을 목표로 두고, 각자 약 6~8시간을 학습·통합·오류 대응 여유로 잡는다. 검증된 공수가 아니라 초기 배분이다. 2시간×15일의 하한에서는 빠듯하므로 첫 주에 재산정한다.

| 구간 | A의 중심 작업 | B의 중심 작업 | 반드시 남길 결과 |
|---|---|---|---|
| D1~3 | 실행, 도형, 부모 카메라, 이동·자전 | 한글 패널, 첫 퍼즐 도면·대사·기록 | 두 PC에서 방과 한글 표시 |
| D4~6 | 상세보기 공전·확대, 입력 복귀 | 뒷면 표식, 4개 카드, UI 내용 | **5가지 기능 전부 실제 시연** |
| D7~9 | 충돌·조사·과거 상태·복귀 | 현재/과거 배치, NPC 2명 | 첫 시야 퍼즐을 직접 탐색 |
| D10~12 | 안개·흡입·추론 판정 연결 | 대사 수정·오답·결과·수동 테스트 | 조사 시작부터 결과까지 |
| D13~15 | Release와 오류 수정 | 외부 플레이·조작법·발표 | 다른 PC에서 제출본 실행 |

B가 자체 UI 엔진 전체를 맡지 않는다. A가 연결한 함수·자료 목록에 B가 고정 콘텐츠를 입력한다. 두 사람이 각자 전체 시스템을 따로 만드는 방식은 피한다.

## 2주만 가능할 때

기능 내용은 바꾸지 않고 표현을 단순하게 한다. 방 하나·잔향 하나·2 NPC·4카드·주장 하나의 성공 루프를 유지한다. FMOD, Assimp, 광원 보강, 상세 메뉴 디자인, 실제 카메라 전진을 보류한다. 한글은 고정 패널 방식도 허용하고 공전·부모·확대는 절대 선택 기능으로 바꾸지 않는다.

D1~3 기반, D4~5 카메라 5가지, D6~7 과거·조사, D8 결과 연결, D9~10 검증이다. 이 일정도 첫 주 결과가 뒷받침해야 한다. 따라잡지 못하면 기술 데모만 가능하다는 점을 보고하고 남은 기간에 5가지 구현을 보호한다. 이것을 게임 완성으로 표시하지 않는다.

## 중간 판단

- D3 한글과 도형이 안 나오면 맵·사건 확대를 멈추고 원인을 해결한다.
- D6 공전·부모가 없으면 잔향 수·외부 모델을 늘리지 않는다.
- D9까지 복귀가 불안정하면 연출보다 저장/복원부터 고친다.
- 마지막 2일은 검증·패키징에 둔다. 새 대형 기능을 넣지 않는다.
- 핵심 완료 뒤에만 선택 확장을 한다. 전체 사건 해결은 시간이 아니라 충분한 증거 설계가 확보된 경우에만 추가한다.

## 작업 습관

오늘 할 일을 ID 하나로 고르고 변경 파일·실행 결과를 적는다. 학습 시간이 길어질 때 작은 항목을 더 쪼개되 작업 항목 개수를 생산성으로 평가하지 않는다. 통합 파일·프로젝트 설정은 A가 정리하고, 상대의 수정 파일을 통째로 덮어쓰지 않는다. 문서 분할 개수와 제품 소스파일 개수는 별개다.
