# 복도 시험 장면 모델 전달 (2026-11-14)

기준: `feature/player-camera`의 `96539cf`. 원본 `asset/corridor/obj/corridor.obj`와 MTL은 수정하지 않았습니다. 기존 합본에서 문·문틀·캐비닛을 분리해 재사용했으며 게임 소스는 수정하지 않았습니다.

## 파일과 재사용

- `corridor_static.obj`: 원본 333개 파트 중 320개. 기존 벽·바닥·천장·장식 유지. 끝벽/문 291~303은 제외.
- `door_frame.obj`: 끝벽 양옆 + 기둥 + 상부 표시등/틀(292,293,297,298,302,303).
- `door_left.obj`, `door_right.obj`: 좌우 문짝. 손잡이·표시등을 각각 포함.
- `cover_cabinet.obj`: 원본 좌측 캐비닛 313~319 재사용. 바닥 기준 원점으로 분리. 원래 벽에 붙어 있던 캐비닛들은 합본에도 그대로 남아 있습니다.
- `materials.mtl`: 기존 MTL 복사. 색상·Ks·Ns 기반이며 PBR 텍스처/UV는 원본에 없습니다. 텍스처 완성본으로 표시하지 않습니다.
- `scene_manifest.json`: 모델별 실제 AABB, 부모 관계, 초기 자세, 위치, 문 이동축, 충돌 프록시.
- `validation_report.json`: 파일 구조 및 합성 배치 검사 결과. 게임 검증과 구분.

**중요:** 원본 `part_291`은 문 뒤를 통째로 막는 박스입니다. 문짝만 이동시키면 계속 막힌 채 보입니다. 시험용 파생 복도에서는 이 박스를 제외했습니다. 원본 합본과 파생 복도를 동시에 그리지 마세요.

## 좌표/치수

단위 m, +Y 위, 문 정면 +Z. 복도 진행은 -Z입니다. 원본의 `(0,0.028,3)`을 새 원점 `(0,0,0)`으로 삼습니다. 즉 원본 좌표에 `(0,-0.028,-3)`을 더합니다. 전체 테스트 장면을 옮길 경우 모든 배치와 충돌 프록시에 동일한 부모 변환을 적용하세요.

- 입구 바닥 중심: `(0,0,0)`
- 문틀 원점/문 평면: `(0,0,-17.81)`
- 통과 확인 목표: `(0,0,-18.15)` (문 바깥으로 이어지는 공간은 추가 제작되지 않음)
- 벽 패널 사이 폭: 6.62
- 리브/장식을 피한 보수적 통행 폭: 6.19 (`x=-3.095..3.095`)
- 보수적 천장 높이: 3.392 (장식물 하단 기준)
- 바닥 패널 윗면: y=0. 얕은 조명/화살표는 장식으로 보고 바닥 충돌에서 무시.
- 열린 문 유효 폭: 2.75 (`x=-1.375..1.375`), 높이: 3.002
- 엄폐물 원본 로컬 크기: 0.589 × 1.14 × 1.03 (X,Y,Z)
- 엄폐물 시험 배치: `(-1.2,0,-8.4)`, Y축 +90도 회전. 배치 후 폭 1.03, 깊이 0.589.

## 조립

1. `corridor_static.obj`를 identity로 배치.
2. 문틀을 `(0,0,-17.81)`에 배치.
3. 문틀 자식인 왼쪽 문은 `(-0.72,0,0)`, 오른쪽 문은 `(0.72,0,0)`에 배치.
4. 문은 회전 경첩이 아니라 슬라이딩입니다. 왼쪽은 -X, 오른쪽은 +X로 각 1.45m 이동. 완전 열림 자식 위치는 `(-2.17,0,0)` / `(2.17,0,0)`.
5. 문짝 충돌 AABB도 같은 이동을 적용. 열림 순간 충돌 전체를 무조건 끄지 말고 실제 위치를 따라가도록 처리.
6. 엄폐물은 별도 오브젝트로 배치. JSON의 cover 프록시는 위 +90도 배치에 맞춘 월드 AABB입니다.

모든 OBJ의 로컬 원점은 해당 부품 바닥 기준입니다. 원본에서의 정확한 절삭/변환 기준은 `source_origin`, `source_parts`로 재현할 수 있습니다.

## 충돌 연결 주의

`static_colliders`는 렌더 메시에 꼭 맞는 충돌이 아니라 시험용 보수적 AABB입니다. 작은 패널 틈으로 빠지거나 장식에 걸리는 것을 막도록 바닥·벽·천장을 연속 프록시로 묶었습니다. 벽은 좌/우 별도이며, 끝벽은 좌/우/상부로 분리해 문 구멍을 남겼습니다. 중앙 통로를 막는 전체 복도 AABB 하나를 사용하면 안 됩니다.

문짝은 `assets`의 실제 로컬 bounds에 부모/자식 위치를 적용하세요. 임의 회전 장면에서는 min/max에 위치만 더하지 말고 AABB 8개 꼭짓점을 월드 변환한 뒤 다시 계산해야 합니다. 계단/점프용 정밀 충돌이나 근접 벽 시각 오차는 게임 연결 후 조정해야 합니다.

## 검증 상태

- 원본 SHA256 유지 확인.
- 다섯 OBJ 삼각형, 인덱스, 유한 좌표, 법선 방향/면 winding, MTL 참조, bounds 일치 검사 통과.
- 반경 0.3m/높이 1.8m AABB를 사용하는 합성 중앙 경로 검사: 정적 장애물과 열린 문은 통과, 닫힌 문은 차단.
- 기존 로컬 Debug `AEGIS.exe --inspect-obj`로 다섯 OBJ 모두 로드 성공. 삼각형 수: 복도 14112, 문틀 264, 문짝 각 132, 엄폐물 308.
- **미검증:** 실제 게임 화면 표시, 플레이어 충돌, 문 애니메이션, 게임 재질 표시. 현재 기준 `GameScene`은 드론만 그리므로 실제 연결은 코딩 담당 단계입니다.
- `--inspect-obj` 검사는 새 빌드 성공이나 실제 게임 표시 성공을 의미하지 않습니다.

재생성: `py -3 tools/prepare_corridor_test_assets.py`

정적 검사: `py -3 tools/check_corridor_test_assets.py`

로더 검사: `AEGIS.exe --inspect-obj <OBJ 절대경로>` (각 파일 별도)
